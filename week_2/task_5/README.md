# День 10 — три стратегии контекста

«Мастерская графики и арта» — помощник для вопросов о 2D и 3D, материалах, свете, композиции и рендеринге. Можно обсудить задачу, уточнить условия и продолжить разговор в разных вариантах.

Это развитие [агента Дня 9](../task_4/README.md) на том же стеке: Python 3.11+, Flask, httpx, SQLite, tiktoken, HTML/CSS/JavaScript и gpt-5.6-luna через прямой OpenAI Responses API. Исходники предыдущей версии использованы как основа; запуск других заданий не требуется. Память, политики и учёт расходов сохранены. Сжатие истории остаётся доступно в предыдущей версии; в трёх режимах этого задания summary не используется.

## Запуск

Из папки задания в PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Если `.env` уже есть, сохраните его. Укажите `OPENAI_API_KEY` с доступом к модели, затем запустите:

```powershell
.\.venv\Scripts\python.exe app.py
```

Откройте http://127.0.0.1:5010. Debug/reload выключены: после изменения Python или конфигурации нужен перезапуск. Один процесс приложения обслуживает одну папку данных; не запускайте второй процесс с теми же БД. Папка по умолчанию — `data/`, её можно изменить переменной `CHAT_DATA_DIR`. Первый запуск tiktoken может загрузить словарь o200k_base.

## Стратегии

| Режим | Контекст основного запроса | Поведение |
|---|---|---|
| Sliding Window | Последние N реплик | Старый префикс отбрасывается из контекста |
| Sticky Facts | Словарь facts + последние N реплик | Явные пользовательские данные обновляются отдельным вызовом перед каждым ответом |
| Branching | Полный путь выбранной ветки | Checkpoint и независимые продолжения с общим префиксом |

N по умолчанию равно 6 и задаётся через `keep_last_messages` в `agent/config.toml`. Одно сообщение — одна реплика пользователя или ассистента; текущий вопрос входит в эти шесть. Постоянные инструкции передаются отдельно. В Facts дополнительный блок словаря не входит в N.

Переключатель открывает три независимых сохраняемых чата. История, facts и checkpoint не переносятся между стратегиями. Полный архив доступен для просмотра, но сборщик Sliding/Facts читает только последние N реплик. Запрос не содержит `previous_response_id`; скрытая серверная история, автоматическая обрезка и summary не используются.

Facts обновляются по предыдущему словарю и текущему сообщению пользователя. Исправленные значения заменяют прежние, отменённые факты должны удаляться. Словарь содержит до 32 ключей, ключ — до 80 символов, строковое значение — до 500. Программа проверяет JSON, уникальность ключей, типы, размеры и корректность Unicode. Правильность выделения фактов зависит от модели: местоимения и ссылки на далёкие ответы могут быть неоднозначны. Полного архива у обновляющего вызова нет.

При неуспешном обновлении facts основной запрос не выполняется, прежний словарь сохраняется, доступные расходы попытки учитываются. Успешное обновление остаётся в памяти, даже если последующий основной ответ не получен. Скрытых повторных вызовов нет.

В Branching сохраните checkpoint, затем создайте от него две именованные ветки. Создание сразу открывает новую ветку. Переключайтесь в блоке веток и продолжайте выбранный путь. Checkpoint неизменяем: последующие сообщения исходной ветки его не меняют. Общие сообщения используются по ссылкам, новые сообщения принадлежат только своей ветке. Состояние восстанавливается после перезапуска.

Полная история ветки растёт. Ветвление разделяет варианты разговора и само по себе не ограничивает размер контекста. При превышении лимита API возвращается ошибка, без скрытого сжатия.

## Использование

Пример начала разговора: «Делаю вечерний портрет: тёплый ключевой свет, холодный фон. Почему лицо теряется на фоне?» Позже уточните условие: «Акцент теперь на силуэте». В режиме Facts можно увидеть актуальную память, а в Branching — сравнить два варианта освещения от одной точки.

Интерфейс показывает полные вопросы и ответы, словарь, ревизии, ID реально отправленных сообщений, оценку контекста, отдельные расходы ответов и обновлений памяти. Предпросмотр Facts использует текущий словарь: будущий результат обновления ещё неизвестен. Локальная оценка текста не равна фактическому usage API.

## Реальное сравнение

[Сохранённый результат](results/reference.json) содержит 12 одинаковых пользовательских вопросов и независимо полученные ответы в каждом режиме. Темы: силуэт, растр/вектор, UV, roughness, нормали, mipmaps, texel density, проекции, цветовые пространства и тени. В первом вопросе явно заданы шесть условий проекта. В седьмом меняются размер текстуры и акцент. Вопросы 6 и 12 просят «текущие условия моего проекта с учётом всех исправлений» и проверяют память после выхода условий из окна.

Модель, инструкции основного ответа и настройки одинаковые: gpt-5.6-luna, reasoning — none, максимальный ответ — 1600 токенов, N = 6 отдельных сообщений с учётом текущего вопроса. В обычных вопросах запрошено до 35 слов; проверки памяти явно требуют JSON. Режимы пройдены последовательно: Sliding Window, Facts, Branching. Каждый чат начинается пустым. Готовые ответы не подставляются.

| Показатель общего сценария | Sliding Window | Facts | Branching, основная ветка |
|---|---:|---:|---:|
| Пользовательские вопросы | 12 | 12 | 12 |
| Основные / служебные вызовы | 12 / 0 | 12 / 12 | 12 / 0 |
| Input tokens | 5 949 | 10 931 | 9 581 |
| Output tokens | 617 | 1 223 | 672 |
| Total tokens | 6 566 | 12 154 | 10 253 |
| Стоимость, USD | 0.0019302 | 0.0036538 | 0.00237750 |
| Верные поля памяти | 0 / 12 | 12 / 12 | 12 / 12 |
| Полные проверки памяти | 0 / 2 | 2 / 2 | 2 / 2 |

Sliding Window ответил null на все ранние условия. Facts и полная ветка сохранили название проекта, Blender, Godot, запрет фототекстур, значения 512/бирюзовый в первой проверке и исправленные 1024/янтарный во второй.

На этом разговоре Facts использовал на 18.5% больше токенов, чем полная ветка. В его расход входят все 12 обновлений словаря. Короткий сценарий не доказывает экономию на длинной истории. Денежное сравнение зависит от кеша: у основной ветки 2270 токенов чтения кеша и 1270 записи, у остальных режимов — ноль. Кеш провайдера не контролировался.

Проверка памяти сравнивает значения с независимым ожидаемым набором. Для размера текстуры допускается целое число или точная десятичная строка: контрольный промпт не задаёт тип. В результате сохранены исходные ответы, словарь facts после каждого хода, ID переданных сообщений, usage и стоимость.

От общего checkpoint созданы две ветки с мягким и жёстким светом, по продолжению и контрольному вопросу в каждой. При переключении они сохранили разные решения; конкретный размер источника не был задан и не выдумывался. Четыре дополнительных вызова: 5 816 токенов, 0.00039880 USD. Общий префикс не считается повторно выполненным: весь branching-чат с продолжениями — 16 вызовов, 16 069 токенов, 0.00277630 USD.

### Качество и удобство

Сохранение фактов и правильность объяснений — разные свойства. Основной смысл roughness, проекций и цветовых пространств передан, но в ответах есть ограничения:

- В Facts ответ о mipmaps неоднозначно говорит о снижении нагрузки на память. Полный набор mip-уровней увеличивает объём хранения обычной 2D-текстуры примерно на треть, хотя улучшает выборку и снижает требования к пропускной способности памяти. Это различие описано в [документации Godot](https://docs.godotengine.org/en/4.3/tutorials/assets_pipeline/importing_images.html#mipmaps-generate).
- В Branching в объяснении roughness появилось постороннее слово «Daarmee». Это дефект языка ответа.
- В жёсткой ветке совет приблизить источник не обоснован: при неизменном размере площадного источника и положении объекта относительно принимающей поверхности сближение увеличивает угловой размер и обычно смягчает тень. Для жёсткости следует уменьшать угловой размер источника.
- UV-развёртка сама по себе не гарантирует уменьшения растяжений или отсутствия наложений. Краткие ответы упрощают роль правильной развёртки. Упоминания теней в объяснениях нормалей также не различают локальное затенение и геометрическую видимость источника.

Исходные ответы оставлены в результатах. Проверки input/output policy оценивают техническую допустимость, а не физическую истинность. Это один прогон с независимыми ответами и неконтролируемым кешем, без пользовательского исследования удобства и без универсального рейтинга стратегий.

По взаимодействию: Sliding требует повторно сообщать старые условия; Facts показывает сохраняемые значения, но добавляет ожидание и возможные ошибки извлечения; Branching сохраняет альтернативы, но требует явно выбрать checkpoint и активную ветку. Это наблюдения по реализованному интерфейсу.

Повторить эксперимент через API, с новыми именами результата и папки данных:

```powershell
.\.venv\Scripts\python.exe comparison.py --output results/my-run.json --data-dir data/my-run
```

Команда расходует токены. Если выбранный результат или каталог уже существует, выполнение останавливается, чтобы не перезаписать предыдущий прогон. Интерфейс читает `results/reference.json`; другой отчёт можно выбрать переменной `CHAT_COMPARISON_PATH`, указав путь к JSON внутри папки задания перед запуском приложения.

## Политики и стоимость

Конфигурация агента содержит input policy `nonempty_text`, output policy `completed_text` и инструкции модели. Входная проверка требует непустую UTF-8-строку в пределах максимума длины. Выходная проверка требует завершённый непустой текст без refusal и корректную структуру ответа; у facts дополнительно проверяется словарь. Отклонённый ответ не становится успешным сообщением ассистента. Пользовательский вывод по умолчанию запрашивается без Markdown, но программной очистки Markdown нет.

SQLite сохраняет actual input/output/total tokens, cached input, cache write и reasoning, если они сообщены API, стоимость каждого вызова, тариф, модель, режим обслуживания, источник/дату проверки и результаты политик. Reasoning уже входит в output и повторно не оплачивается. Общий расход режима включает все его ветки и служебные вызовы ровно по одному разу. При неизвестных данных сумма явно неполная; отсутствие вызова отличается от отсутствующего usage.

Стандартный тариф [Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna), проверенный 14 сентября 2026: за миллион токенов input 0.20 USD, cached input 0.02 USD, cache write 0.25 USD, output 1.20 USD. Расчёт применяется только при совпадении модели/режима и входе до 272000 токенов; вне поддержанного тарифа стоимость неизвестна. Оценка не заменяет счёт провайдера.
