# День 9 — сжатие истории

Помощник по игровому арту с двумя режимами контекста: полная история и summary старой части разговора с последними сообщениями без изменений. Помогает обсуждать бриф, моделирование, UV, материалы и подготовку игрового ассета.

Это следующая версия [агента Дня 8](../task_3/README.md), сохраняющая его стек, память, политики и учёт расходов. Исходники находятся здесь; запуск предыдущих заданий не требуется. Python 3.11+, Flask, httpx, SQLite, tiktoken, HTML/CSS/JavaScript. Модель — gpt-5.6-luna через прямой OpenAI Responses API.

## Запуск

Нужен API-ключ OpenAI с доступом к модели. В PowerShell из папки задания:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Если `.env` уже существует, не перезаписывайте его. Укажите в нём `OPENAI_API_KEY`, затем:

```powershell
.\.venv\Scripts\python.exe app.py
```

Откройте http://127.0.0.1:5009. Debug и reload выключены; после изменения конфигурации нужен перезапуск. Первый запуск tiktoken может загрузить словарь o200k_base из интернета.

## Как пользоваться

Выберите «Со сжатием» или «Без сжатия». Это два независимых чата: переключение не переносит переписку. Сохранённая история восстанавливается после перезапуска. Введите бриф, затем уточняйте решения и задавайте вопросы о предыдущих сообщениях. Можно загрузить UTF-8 `.txt` в поле; отправка выполняется отдельно.

Пример: «Бриф: сундук Кедр-731, 1500 треугольников, текстура 512×512, бирюзовый акцент». Позже исправьте бюджет на 1200 и цвет на янтарный. После нескольких сообщений попросите напомнить актуальные ограничения.

В интерфейсе доступны:

- исходный диалог и usage каждого запроса;
- предварительная оценка токенов полного архива перед отправкой;
- summary, его размер, ревизия и граница сжатия;
- сообщения после границы сжатия с исходными ролями и текстами;
- общий расход чата и отдельный расход на summary;
- сохранённое сравнение режимов на одинаковой истории, с конкретными ответами и ожидаемыми фактами.

Предварительная оценка полного архива не является оценкой будущего summary и не заменяет фактический usage API. Финальный состав отправленного контекста дополнительно фиксируется в метаданных запроса.

## Механизм и допущения

Одна реплика пользователя или ассистента — одно сообщение. В `agent/config.toml` независимо задаются `summary_every_messages = 6` (интервал) и `keep_last_messages = 6` (число сохраняемых дословно реплик).

Перед ответом агент проверяет число сообщений, накопленных после последнего успешного сжатия. Текущий новый вопрос в интервал ещё не входит. Когда накоплено минимум шесть предыдущих сообщений и есть старая часть за пределами последних шести реплик, агент обновляет summary. Поэтому в обычном диалоге первое сжатие происходит перед ответом №4, следующие — перед №7, 10, 13 и далее: раз в три пары «вопрос — ответ».

Сразу после сжатия контекст запроса содержит summary и последние шесть сообщений, включая текущий вопрос. Между сжатиями несжатая часть растёт и передаётся полностью: сообщения не выбрасываются в ожидании следующего интервала. Для 24 вопросов с успешными ответами выполняются семь вызовов summary. Если сообщений для старого префикса недостаточно, сжатие откладывается даже при достигнутом интервале.

Пересказ получает предыдущий summary и только новые сообщения, вышедшие за сохраняемую часть. Инструкции агента остаются отдельно; summary передаётся как недоверенная справочная память. Целевой размер пересказа — 150–200 токенов, программный максимум — 400 локальных токенов o200k_base; лимит генерации summary — 600 токенов API. Локальный подсчёт может отличаться от провайдерского.

Исходные сообщения сохраняются в SQLite. Отдельная таблица `context_memory` хранит summary, границу охваченной истории и ревизию. Успешный пересказ, граница и метаданные интервала сохраняются атомарно. После перезапуска интервал продолжается с последнего успешного сжатия; для старых баз граница интервала восстанавливается по связанному пользовательскому запросу.

При ошибке API, отклонении или превышении лимита summary память и отсчёт интервала не меняются. Основной запрос не отправляется, расходы попытки сохраняются. Скрытых повторов нет: повторная попытка возможна при следующем запросе пользователя.

В таблице «Как растёт расход» № означает последовательность выполнения операций, а не внутренний ID записи. Сжатие располагается перед ответом, который использует его результат. «Токенов за вызов» равно входу плюс выходу этой строки; «Токенов за чат» — накопленная сумма. Оценки полного архива остаются в карточках сообщений и не прибавляются к фактическому usage.

## Сравнение качества и расходов

[Текущий результат](results/reference.json) — полный прогон с пустой истории: 24 одинаковых пользовательских вопроса по компьютерной графике в каждом режиме, по 24 реально сгенерированных ответа. Итог — по 48 реплик. Ни готовые ответы, ни начальная история не подставляются; контрольные сообщения не удаляются. Учитываются все API-вызовы с первого вопроса. Ответы режимов могут различаться и остаются в собственной истории каждого режима.

Темы: растровая и векторная графика, проекции, сглаживание, преобразования координат, нормали, UV, texel density, mipmaps, фильтрация, карты поверхности, PBR, цветовые пространства, прозрачность, depth buffer, culling, LOD, batching, освещение и трассировка лучей. В шесть вопросов включены проверки памяти об исходном брифе и его изменениях. Порядок вызова режимов чередуется. Полная последовательность и оба набора ответов доступны в блоке сравнения интерфейса.

| Показатель за весь диалог | Без сжатия | Со сжатием |
|---|---:|---:|
| Вопросы / все реплики | 24 / 48 | 24 / 48 |
| Основные вызовы / вызовы summary | 24 / 0 | 24 / 7 |
| Все входные токены | 52 559 | 30 828 |
| Все выходные токены | 2 043 | 3 480 |
| Всего токенов | 54 602 | 34 308 |
| Из них создание и обновление summary | 0 | 7 581 |
| Стоимость, USD | 0.00506875 | 0.00925688 |
| Проверки памяти | 6/6 | 6/6 |

На всём диалоге сжатие сократило расход на 20 294 токена, или 37,2%, включая все расходы summary. На первых шести вопросах оно было дороже по токенам: 5 411 против 5 024; на длинном разговоре сокращение повторно отправляемой истории стало существеннее.

Денежная стоимость выросла примерно на 82,6%. Полный режим получил 44 995 токенов чтения кеша и 4 089 токенов записи, сжатый — 8 769 и 9 874 соответственно. Разное состояние кеша и генерация summary влияют на стоимость; этот прогон не доказывает денежную экономию или преимущество при одинаковом состоянии кеша. Тарифы в отчёте — сохранённый снимок конфигурации с указанной датой проверки.

Оба режима сохранили все шесть проверяемых наборов фактов, включая ранние ограничения и неизвестное время ревью. Это результат одного прогона на конкретных вопросах, а не гарантия отсутствия потерь при последующих пересказах или в других диалогах.

Проверка требует JSON с непустым explanation и точного совпадения остальных ключей, типов и значений с независимо заданными ожидаемыми фактами. Она измеряет память, а не научную точность, полноту или полезность объяснений теории. Проведён один прогон каждого режима; независимые ответы и неконтролируемый кеш ограничивают обобщение результатов.

Предыдущие измерения сохранены: [продолжение подготовленной истории](results/prepared-history.json) с экономией 6,8% и [вариант с длинным summary](results/initial.json) с перерасходом 15,9%. Они используют другую методику и не являются повторами текущего полного прогона.

Повторить полный эксперимент (платные API-вызовы):

```powershell

```

Каждый запуск создаёт отдельные базы и отчёт в `data/dialogue-24-<идентификатор>/`, итоговый отчёт — `data/comparison.json`. Сохранённое сравнение в интерфейсе использует `results/reference.json` и не перезаписывается автоматически. Ручные чаты не участвуют в эксперименте.

## Учёт, политики и ограничения

Usage берётся из API. `total_tokens = input_tokens + output_tokens`; reasoning входит в output и не прибавляется повторно. Отдельно учитываются чтение/запись кэша. Все основные вызовы и вызовы summary, включая отклонённые выходной политикой, сохраняют доступные токены, цену, модель, режим обслуживания, тарифный снимок и результат политик. Отсутствие вызова отличается от неизвестного usage. Неполные итоги обозначаются `+ ?`.

Стандартный тариф Luna проверен 13 сентября 2026 года: USD за миллион токенов — вход 0.20, чтение кэша 0.02, запись кэша 0.25, выход 1.20. [Источник цен](https://developers.openai.com/api/docs/pricing), [характеристики модели](https://developers.openai.com/api/docs/models/gpt-5.6-luna). Стоимость считается через Decimal:

```text
ordinary = input_tokens - cached_tokens - cache_write_tokens
USD = (ordinary × 0.20 + cached_tokens × 0.02
       + cache_write_tokens × 0.25 + output_tokens × 1.20) / 1 000 000
```

Это оценка по тарифу, не счёт провайдера. Для несовпадающих модели/режима, неполного usage и входа свыше 272 000 токенов цена неизвестна: длинный тариф не реализован. Справочные лимиты модели — окно 1 050 000 и максимальный вход 922 000 токенов. Ошибки переполнения, квоты, сети и незавершённой генерации различаются.

Input policy проверяет строку, непустой текст после trim, Unicode и длину до 8 000 000 символов. Она применяется к новому сообщению до любого LLM-вызова, а также к сформированному входу компрессии. Output policy проверяет completed-статус, структуру, отсутствие refusal и непустой текст; для summary дополнительно проверяется размер. Тематичность, достоверность и обычный текст без Markdown заданы инструкциями, а не программной проверкой смысла. Явный запрос пользователя на другой формат имеет приоритет.

Базы `data/full.sqlite3` и `data/compressed.sqlite3`, ключ и кэш исключены из Git. Один локальный пользователь и один процесс на каталог баз. Для новых чатов остановите приложение и задайте новый каталог:

```powershell
$env:CHAT_DATA_DIR = "data/new-chats"
.\.venv\Scripts\python.exe app.py
```

Старые базы сохраняются. При прерывании процесса незавершённые запросы восстанавливаются как interrupted с неизвестным расходом. При сетевом сбое сначала нажмите «Обновить»: ответ мог сохраниться. `store=false` отключает сохранение объекта Response через API, но не является обещанием отсутствия журналов у провайдера. В обоих режимах часть переписки отправляется облачной модели; локальный архив не означает полностью локальную обработку.

```powershell

```

Тесты не выполняют платных API-вызовов. Проверяют политики, payload, транзакционное восстановление, первую/повторную компрессию, исходный хвост, отказ summary, лимит пересказа, полный режим, usage/стоимость, строгий оракул и изоляцию HTTP-режимов.

- `agent/` — конфигурация, политики, управление контекстом, SQLite, токенизация, API и стоимость.
- `app.py`, `templates/`, `static/` — веб-интерфейс и HTTP-адаптер.
- `comparison.py`, `dialogue_experiment.py`, `results/` — запуск, 24 вопроса и реальные результаты сравнения.
- `tests/`, `pytest.ini`, `requirements.txt`, `.env.example` — проверки и самостоятельная установка.
