# День 8 — токены и стоимость диалога

Локальный помощник по игровому арту: обсуждает бриф, моделирование, UV, текстурирование и ограничения игровых ассетов. Сохраняет диалог после перезапуска и показывает, сколько токенов занимает история и сколько расходуется при каждом обращении к модели.

Это развитие [агента с памятью Дня 7](../task_2/README.md). В папке находится самостоятельная версия его исходников с новыми измерениями; предыдущая версия и её база остаются независимыми. Стек: Python 3.11+, Flask, httpx, SQLite, tiktoken, HTML/CSS/JavaScript. Модель по умолчанию — gpt-5.6-luna через OpenAI Responses API.

## Что показывает приложение

- Предварительную оценку токенов нового сообщения, прошлой истории, инструкций и их суммы — до обращения к LLM.
- Фактические input, output и total из usage каждого ответа API.
- Размер всей сохранённой истории после ответа и накопленные input/output/total всех обращений.
- Стоимость каждого вызова и известную накопленную стоимость чата в USD.
- Отдельные счётчики чтения и записи кэша, reasoning, результаты входной и выходной политик.
- Таблицу роста расходов по ходам и понятную ошибку при настоящем переполнении контекста.

Для короткого и длинного диалога используются одинаковые модель и настройки. Большой искусственный текст служит нагрузкой для проверки лимита. Автоматическая обрезка и сжатие истории в этом задании не реализованы.

## Запуск

Нужны Python 3.11+ и API-ключ OpenAI с доступом к выбранной модели. Команды PowerShell выполняются из папки этого задания:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Если `.env` уже существует, пропустите копирование. В локальном `.env` укажите `OPENAI_API_KEY`, затем запустите:

```powershell
.\.venv\Scripts\python.exe app.py
```

Откройте http://127.0.0.1:5008. При первом запуске tiktoken загружает словарь o200k_base; нужен доступ в интернет. Словарь кэшируется в `data/tiktoken/` (или в каталоге из переменной `TIKTOKEN_CACHE_DIR`).

Пример первого сообщения: «Наш ассет — сундук Кедр-731: 1500 треугольников, текстура 512×512, бирюзовый акцент. Запомни бриф и предложи первый шаг». Затем уточняйте материалы и ограничения. Можно загрузить UTF-8 `.txt` кнопкой «Загрузить бриф»: текст попадёт в поле, отправка выполняется отдельно.

Перезапустите сервер и нажмите «Обновить», чтобы увидеть восстановленные сообщения и расходы. Одна база соответствует одному чату; одновременно с ней должен работать один процесс приложения.

## Как читать числа

Локальный счётчик использует BPE `o200k_base` из tiktoken. Оценка истории — сумма токенов текстов всех предыдущих сообщений, без нового сообщения. К ней добавляются отдельно посчитанные инструкции и новый текст. Эта оценка не включает служебное оформление сообщений провайдером и не доказывает точное соответствие токенизатору модели, поэтому обозначается `≈`.

`input_tokens` — фактический полный вход по данным API, включая повторно переданную историю. `output_tokens` включает reasoning, если он есть. `total_tokens = input_tokens + output_tokens`. Reasoning не прибавляется второй раз.

Размер текущей истории и суммарный расход — разные величины. Например, первое сообщение вновь передаётся во втором, третьем и следующих вызовах, поэтому входит в расход несколько раз. При примерно одинаковых добавлениях вход каждого хода растёт примерно линейно, а суммарный вход — примерно квадратично; кэширование меняет денежную стоимость этого роста.

Метрики до вызова, usage, тариф, модель, режим обслуживания и результаты политик сохраняются вместе с запросом. При отсутствии usage выводится «неизвестно», при отсутствии вызова — «нет вызова». Неизвестная стоимость или usage делает соответствующий накопленный итог неполным (`+ ?`), даже если остальные вызовы посчитаны. Отклонённый выход с доступным usage включается в расходы.

## Тариф и ограничения

В `agent/config.toml` явно заданы источник тарифа, дата проверки, модель и стандартный режим обслуживания. Тариф gpt-5.6-luna, проверенный 13 сентября 2026 года, в USD за миллион токенов:

| Категория | USD / 1 млн |
|---|---:|
| Обычный вход | 0.20 |
| Чтение кэша | 0.02 |
| Запись кэша | 0.25 |
| Выход, включая reasoning | 1.20 |

Чтение и запись кэша входят в input. Формула:

```text
ordinary_input = input_tokens - cached_tokens - cache_write_tokens
cost_usd = (ordinary_input × 0.20 + cached_tokens × 0.02
            + cache_write_tokens × 0.25 + output_tokens × 1.20) / 1 000 000
```

Запись кэша заменяет обычную цену соответствующих входных токенов, а не добавляется поверх неё. Расчёт выполняется через Decimal. Это оценка по опубликованному тарифу, не счёт провайдера. Если модель/режим не совпадают, счётчики неполны или некорректны, либо вход превышает 272 000 токенов, стоимость остаётся неизвестной: отдельный тариф длинного контекста здесь не реализован. Старые записи не пересчитываются задним числом.

Источники: [характеристики и цены модели](https://developers.openai.com/api/docs/models/gpt-5.6-luna), [учёт кэширования](https://developers.openai.com/api/docs/guides/prompt-caching), [токенизатор tiktoken](https://github.com/openai/tiktoken).

Справочные ограничения модели в конфиге: окно 1 050 000 токенов, максимальный вход 922 000. Ответ ограничен приложением до 1 600 токенов, reasoning — none. Локальная input policy допускает до 8 000 000 Unicode-символов; символы не равны токенам. HTTP-адаптер допускает JSON до 100 МБ, загрузка файла в интерфейсе — до 32 МБ.

## Что происходит при переполнении

В API передаётся `truncation="disabled"`. При подтверждённом `context_length_exceeded` приложение показывает код и HTTP 400, не создаёт успешный ответ и не выдумывает расход. Ошибки квоты, частоты запросов и незавершённая генерация различаются. [Описание параметра truncation](https://developers.openai.com/api/reference/python/resources/responses/methods/create).

Все сообщения, прошедшие входную политику, сохраняются до вызова API, включая сообщение, вызвавшее переполнение. Поэтому следующая попытка с этой историей тоже может превысить лимит. Для нового чата остановите сервер и задайте отдельный файл БД:

```powershell
$env:CHAT_DB_PATH = "data/new-chat.sqlite3"
.\.venv\Scripts\python.exe app.py
```

Старый чат остаётся в прежнем файле. Для возвращения к базе по умолчанию остановите сервер, выполните `Remove-Item Env:CHAT_DB_PATH` и запустите его снова. Не используйте уже существующий файл, если нужен пустой чат.

Один чат, одинаковые настройки Luna: короткий бриф про сундук и шесть дополнений примерно по 3 276 токенов текста. Дополнения содержат повторяющиеся детали ассета и служат контролируемой нагрузкой; это не естественная длительная переписка. Фактические значения одного прогона:

| Ход | Input API | Output API | Total API | USD вызова | USD чата |
|---|---:|---:|---:|---:|---:|
| 1 | 252 | 87 | 339 | 0.0001548 | 0.0001548 |
| 2 | 3621 | 60 | 3681 | 0.0009771 | 0.0011319 |
| 3 | 6963 | 87 | 7050 | 0.00101286 | 0.00214476 |
| 4 | 10332 | 85 | 10417 | 0.00108405 | 0.00322881 |
| 5 | 13699 | 86 | 13785 | 0.00115213 | 0.00438094 |
| 6 | 17067 | 84 | 17151 | 0.00121732 | 0.00559826 |
| 7 | 20433 | 84 | 20517 | 0.00128418 | 0.00688244 |

Вход с первого по седьмой ход вырос с 252 до 20 433 токенов (примерно в 81 раз). Суммарно API сообщил 72 367 входных и 573 выходных токена — 72 940 всего. История в этот момент занимает примерно 20 249 токенов текста: накопленный расход больше из-за повторных передач. Стоимость последнего вызова выросла примерно в 8.3 раза относительно первого; чтение уже записанного кэша дешевле обычного входа, поэтому деньги не растут пропорционально input.

Восьмой запрос: явно обозначенный искусственный бриф с 1 100 000 повторений « art», всего 4 400 143 символа. Вместе с историей и инструкциями локальная оценка — 1 120 481 токен. Реальный API вернул HTTP 400 и context_length_exceeded, без usage и без ответа модели. Итог после этой попытки: известные 72 940 токенов + неизвестный расход, известные $0.00688244 + неизвестная стоимость. Точная граница срабатывания не измерялась; проверен заведомо превышающий её вход. Результаты отдельных повторов могут отличаться из-за ответа модели и кэширования.

## Память и политики

SQLite по умолчанию хранится в `data/chat.sqlite3`. Тексты сохраняются для памяти диалога; для учёта расходов используются отдельные записи метаданных. При каждом обращении полная история и инструкции отправляются провайдеру. `store=false` отключает сохранение Response как объекта API; это не заявление об отсутствии всех журналов у провайдера. База, ключи и кэш исключены из Git.

Input policy проверяет тип, непустой нормализованный текст, допустимый Unicode и длину до вызова LLM. Output policy проверяет completed-статус, структуру текстового ответа, отсутствие refusal и непустой текст. Отклонённый ответ не добавляется как сообщение агента, но его usage и стоимость сохраняются. Прерванный запрос после перезапуска получает статус interrupted с неизвестным расходом; скрытого повтора нет.

Тематичность, достоверность и соблюдение обычного текстового формата задаются инструкциями модели, а не программной проверкой смысла. Формат по умолчанию — текст с абзацами без Markdown; явный запрос пользователя на другой формат имеет приоритет.

## Проверка и состав

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты проверяют политики, состав payload, сохранение/восстановление, токены второго хода, стоимость чтения и записи кэша, reasoning без двойного счёта, неполные итоги, ошибки API и HTTP-адаптер. Платных запросов в pytest нет; при отсутствии словаря первый запуск может загрузить его.

- `agent/config.toml`, `agent/config.py` — настройки и их проверка.
- `agent/core.py` — агент, политики и цикл запроса.
- `agent/tokens.py`, `agent/usage.py` — локальные оценки, usage и стоимость.
- `agent/storage.py` — транзакционная память и журнал обращений.
- `agent/transport.py` — прямой вызов Responses API и классификация ошибок.
- `app.py`, `templates/`, `static/` — локальное веб-приложение.
- `tests/`, `pytest.ini`, `requirements.txt`, `.env.example` — проверки и запуск.
