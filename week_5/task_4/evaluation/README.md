# Десять вопросов к локальному корпусу

`questions.json` фиксирует десять вопросов с проверяемыми фактами. Все десять имеют ответ в индексированных README и исходниках помощника; это диагностический набор о самом проекте, а не энциклопедия компьютерной графики. Вопрос q04 относится к настроенным платформам источников и количеству возвращаемых фрагментов. Пример normal mapping в README не означает, что учебный материал об этом содержится в индексе.

`scripts/evaluate_grounding.py` последовательно создаёт отдельный чистый диалог для каждого вопроса и вызывает тот же `RagProfileWorkspace.agent().run(..., rag_mode='filter')`, что обслуживает основной чат. Служебная история, working и long-term memory в этих диагностических диалогах не нужны; каждая попытка выполняется один раз без скрытого повтора. Скрипт использует проверенную копию индекса в отдельной области рядом с выходным JSON. Основное хранилище `--data-dir` он только читает. Выходной путь должен быть новым.

```powershell
.venv\Scripts\python.exe -B scripts/evaluate_grounding.py --data-dir data --output docs/day24-live.json --env-file .env
```

Экспорт после каждой попытки атомарно обновляет полный ответ, сохранённые requests с usage и USD, выбранные и действительно использованные фрагменты, фактические payloads Responses API и структурные признаки. Содержимое API-ключа не включается в payload. Сохраняются хеши набора вопросов, исходного и рабочего индекса, идентификаторов проверенных чанков и конфигурация поиска. При исключении остаётся частичный JSON с типом ошибки и payloads уже начатой попытки; оплаченные стадии остаются в журнале диалога. `complete_structural` означает лишь, что все десять ответов прошли программную проверку связей с фрагментами. Смысловую поддержку каждого утверждения проверяет отдельный рецензент по полным текстам источников; до этого поле `assessment` остаётся `pending_independent_review`. Отказ на любом из этих десяти вопросов означает неполный результат. Отказ при отсутствии сведений проверяется отдельным, одиннадцатым сценарием.
