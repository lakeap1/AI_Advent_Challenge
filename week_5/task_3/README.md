# День 23 — реранкинг и фильтрация в RAG-чате

Помощник по компьютерной графике и арту с локальным поиском и модельным отбором источников. В обычном чате доступны режимы без поиска, RAG и RAG + фильтр; отдельный экран сравнивает два последних режима на десяти фиксированных вопросах. Профили, память, задачи, MCP и журнал расходов сохраняются. Код задания самостоятелен: runtime не импортирует предыдущие задания.

## Запуск

Нужны Python 3.11+ и ключ OpenAI. Из папки задания:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
# Укажите OPENAI_API_KEY в локальном .env.
.venv\Scripts\python.exe app.py
```

Основной чат: `http://127.0.0.1:5023/`. Индексация: `/indexing`. `CHAT_DATA_DIR` задаёт расположение локальных SQLite-хранилищ вместо `data/`.

Для поиска нужен совместимый индекс: создайте его на странице индексации или перенесите существующий индекс при остановленном сервере:

```powershell
.venv\Scripts\python.exe -B -m rag.cli import-index --source ../task_2/data/indexing.sqlite3 --data-dir data
```

Перенос проверяет модель embeddings, размерность, корпус, текст и метаданные чанков; существующий индекс не заменяет. Сервер и CLI, изменяющий индекс, запускать последовательно.

## Режимы основного чата

| Режим | Поисковая строка | Второй этап |
| --- | --- | --- |
| `plain` | Поиск выключен | Обычный помощник |
| `rag` | Исходный вопрос | Нет |
| `filter` | Исходный вопрос | Модельная оценка кандидатов |

Производственный API сохраняет прежние режимы `rewrite` и `rewrite_filter` для совместимости с историческими данными, но текущий интерфейс сравнения их не запускает. Фильтр и окончательная генерация получают исходный вопрос. Найденные кандидаты, причины отбора и точный отправленный контекст сохраняются в журнале и доступны в деталях запроса.

`rag/config.toml` задаёт число кандидатов до отбора (`top_k_before=10`), предел источников после отбора (`top_k_after=2`) и порог (`relevance_threshold=2`). После изменения конфигурации перезапустите сервер и начните новый прогон сравнения: уже созданный прогон привязан к прежнему снимку настроек. Шкала: 0 — нерелевантно; 1 — близкая тема без достаточных оснований; 2 — полезные частичные основания; 3 — прямые основания для ответа. Это порядковая оценка модели, а не вероятность.

Фильтр оценивает список кандидатов одним вызовом. Прошедшие порог источники сортируются по оценке, cosine similarity и ID. Перекрывающиеся фрагменты исключаются; окончательный контекст ограничен 6000 UTF-8 байтами. Число выбранных источников может быть меньше двух. Фильтр не может восстановить фрагмент, отсутствующий в первых десяти результатах.

Если ни один источник не подходит, чат возвращает `no_context` и не вызывает генерацию. При ошибке API или отклонённом служебном результате зависимые стадии останавливаются без скрытого повторного запроса. Валидация формы и явных идентификаторов не гарантирует сохранение смысла rewrite или правильность модельной оценки.

## Источники, политики и расходы

База содержит 51 README/файл кода помощника. Она подходит для вопросов о реализации агента, поиске, памяти и MCP; это не энциклопедия компьютерной графики. Обычный режим помогает по графике, а поиск ограничен содержимым локального корпуса. Ссылки [S1], [S2] в ответах соответствуют реально отправленным фрагментам. Проверка известных меток не доказывает смысловую опору утверждений на источник.

Пользовательский ответ запрашивается обычным текстом; служебные стадии используют строгий JSON. Input/output policy принадлежат агенту. Невалидный вход отклоняется до соответствующего API-вызова, невалидный ответ останавливает дальнейшую обработку. Понесённые расходы сохраняются и после отказа.

SQLite хранит фактические input/output/total tokens, cached/reasoning usage при наличии, цену каждого вызова, тариф, модель, режим обслуживания и накопленные расходы чата. Rewrite, embedding, фильтр, генерация и штатное извлечение памяти учитываются отдельно. Неизвестные данные показаны как неизвестные; известная часть суммы не выдаётся за полную стоимость.

Модель и бюджет основного ответа задаёт `agent/config.toml`; параметры служебных стадий и embeddings — `rag/config.toml`. Настройки тарифов содержат источник и дату проверки. Дополнительные стадии увеличивают время и стоимость, поэтому сравнение учитывает оба показателя.

## Контролируемое сравнение

На главной странице откройте «RAG и RAG + фильтр · 10 вопросов». «Новый прогон» создаёт две отдельные ленты без обращения к модели. Набор `evaluation/questions.json` содержит десять фиксированных вопросов и атомарные ожидаемые факты, включая вопрос с отсутствующими данными. Кнопка «Вставить следующий вопрос» переносит точный текст в общий composer; «Отправить в оба чата» выполняет RAG и RAG + фильтр для следующего вопроса. Обычный свободный чат остаётся доступным отдельно. Сохранённые прогоны и вопросы можно открыть повторно без API-вызова.

Обе ветки получают копии одного начального профиля, задачи и памяти. История, working/long-term context и внешние инструменты выключены одинаково. Карточки показывают полный ответ и источники с раскрываемыми фрагментами. «Расходы и политики» открывает общую панель учёта, а отдельный отчёт под чатами показывает качество после независимой оценки. До неё интерфейс отмечает ожидание оценки. Оценка измеряет корректность и поддержку каждого факта, полноту ответа, неподтверждённые утверждения, достаточность кандидатов/контекста, отказ на вопросе без данных, время и USD. Экспорт содержит полные ответы, источники, промежуточные стадии, реальные API-payloads и хеш свидетельств; импорт проверяет привязку оценки к конкретному прогону.

```powershell
.venv\Scripts\python.exe -B -m rag.chat_evaluation_cli --data-dir data --profile-id 1 export RUN_ID evidence.json
.venv\Scripts\python.exe -B -m rag.chat_evaluation_cli --data-dir data --profile-id 1 import assessment.json
```

Десять вопросов дают описательное сравнение на фиксированном корпусе. Они не доказывают общее превосходство режима или качество по всей предметной области. Параметры и эталоны фиксируются до прогона; исторические результаты других путей генерации не заменяют текущий контроль.

### Воспроизводимый benchmark harness

`scripts/run_two_chat_benchmark.py` запускает сравнение на локальном снимке профиля, памяти и индекса. По умолчанию он делает только пробный запуск без платных вопросов. Запускайте его из папки задания при остановленном сервере, с готовым индексом и выбранным профилем; укажите новый путь `--output-prefix`, чтобы сохранить manifest и экспорт. Для платного `--execute` нужен ключ в окружении процесса и актуальный суммарный расход в `--known-spent-usd`: скрипт проверяет общий лимит 1 USD и резерв 0.15 USD перед каждым вопросом. Значение расхода должно включать все предыдущие вызовы, в том числе сделанные после приведённых ниже измерений. Не запускайте платный benchmark параллельно с сервером или другой записью в тот же профиль.

```powershell
.venv\Scripts\python.exe -B scripts/run_two_chat_benchmark.py --data-dir data --profile-id 1 --before 10 --after 2 --threshold 2 --output-prefix data/benchmark-dry --dry-run
```

Для платного прогона используйте те же аргументы, новый `--output-prefix`, `--known-spent-usd` с проверенной текущей суммой и `--execute` вместо `--dry-run`. Дополнительный `--minimum-prior-spend-usd` задаёт известную нижнюю границу расходов; меньшая сумма будет отклонена. Пробный запуск без исходной суммы сохраняет её как неизвестную, а не как ноль. Если нужен сравнительный контроль с параметрами 20/6/2, задайте их аргументами harness: он создаст отдельную копию данных. Прогон с текущими настройками 10/2/2 использует указанное хранилище профиля; поэтому предварительно сохраните нужные данные и не смешивайте его с работающим сервером. Отчёт о качестве требует отдельной проверки ответов и источников; manifest сам по себе её не выполняет.

### Результат текущего двухрежимного сравнения

Один завершённый живой прогон с настройками 10/2/2/6000, фиксированными десятью вопросами и независимой оценкой дал такие результаты. Полный ответ содержит все ожидаемые подтверждённые факты без существенных утверждений без опоры. В стоимость включены все выполненные API-вызовы этого прогона, в том числе служебные.

| Режим | Верные факты / 26 | Подтверждённые факты / 26 | Полные ответы / 10 | Неподтверждённые утверждения | API-вызовы | Стоимость, USD |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| RAG | 13 | 12 | 4 | 2 | 30 | 0.003015525 |
| RAG + фильтр | 23 | 23 | 8 | 0 | 40 | 0.011819685 |

Суммарно: 70 API-вызовов и 0.014835210 USD. Оба режима правильно отказались выдумывать отсутствующее значение на вопросе q10. Фильтр добавил четыре полных ответа относительно RAG на этой выборке. Результат относится к этим десяти вопросам и одному завершённому прогону. Фильтр может остановить запрос до генерации, если модель вернула невалидный служебный JSON. Такое отклонение отображается как ошибка и не считается полноценным ответом. Автоматического повторного запроса нет; выполненные стадии остаются в журнале расходов.

Страница `/rag` и `rag.cli` остаются дополнительными средствами работы с отдельным RAG-сервисом. Сравнение основного помощника выполняется через чат и `rag.chat_evaluation_cli`.
