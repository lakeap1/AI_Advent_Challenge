# День 21. Индексация корпуса документов

Самостоятельная версия помощника по компьютерной графике и арту. Прежний чат, память, персонализация, политики, учёт токенов и стоимости, источники, сводки, композиция и оркестрация MCP сохранены. Страница `/indexing` готовит локальный документный индекс: делит один корпус двумя способами, получает embeddings через OpenAI API и хранит результат в SQLite. Чат пока не использует этот индекс для ответов.

## Корпус и две стратегии

Корпус задан явным списком из 51 UTF-8 файла в `corpus/manifest.json`: исходники сохранённого помощника дня 20 и снимок его README в `corpus/project_readme.md`. За пределы папки задания индексация не выходит. Дубликаты содержимого исключаются по SHA-256; symlink/reparse и небезопасные пути отклоняются. `inspect` показывает фактические документы, символы, строки, хеш и условные страницы. Одна такая страница равна 1800 символам, минимальный объём для построения — 54 000 символов (30 эквивалентов страниц). Это учебная мера объёма, а не физические листы.

`fixed` режет текст на фрагменты до 1800 Unicode-символов с перекрытием 180 символов. `structural` следует заголовкам Markdown и структуре Python; длинные разделы дополнительно делятся на ограниченные фрагменты. С каждым чанком сохраняются точные символьные offsets, строки, разделы, источник, хеш документа, текст и вектор. Сравнение показывает количество и размеры фрагментов, пересечения разделов, fallback, повторённый объём, время, фактические input tokens и оценку USD. Эти показатели описывают структуру и расход; они не доказывают качество будущего поиска или ответов.

Модель — `text-embedding-3-small`, размерность 1536. Запросы идут непосредственно в OpenAI API пакетами до 16 фрагментов. При `build` провайдеру отправляется текст указанных файлов; ключ остаётся на сервере. `indexing/config.toml` содержит параметры и тариф standard $0.02 за миллион input tokens: [официальный источник](https://developers.openai.com/api/docs/models/text-embedding-3-small), проверено 03.10.2026. Оценка по usage не является счётом провайдера. Output tokens для embeddings не применяются. При отсутствующем или некорректном usage стоимость неизвестна, накопленная сумма помечается неполной. Отказ input policy останавливает обработку до API; ошибка API или output policy прекращает дальнейшие пакеты без скрытого повтора, сохраняя доступный расход.

## Установка и запуск

Нужны Python 3.11+, интернет и OpenAI API-ключ для построения. В PowerShell из `week_5/task_1`:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:OPENAI_API_KEY = "ваш ключ"
.\.venv\Scripts\python.exe -B app.py
```

Откройте `http://127.0.0.1:5021/indexing`; чат находится по `/`. Страница, статус и сохранённый индекс доступны без ключа. Кнопка «Индексировать документы» строит обе стратегии. Длительный запрос не захватывает lock чата; состояние можно обновлять во время построения. Повтор без `force` использует готовую пару того же snapshot и контракта без нового API-вызова. Для осознанной перестройки используйте CLI `build --force`. Запускайте один экземпляр приложения на каталог данных.

Переменная `CHAT_DATA_DIR` меняет корень локальных данных. По умолчанию индекс расположен в `data/indexing.sqlite3`. `data/`, ключи и экспорт хранятся локально. Приложение слушает только `127.0.0.1` и не предоставляет сетевую авторизацию.

## CLI и сохранённые данные

Команды выполняются из папки задания. `inspect` читает исходники без открытия базы и без ключа; `summary` и `export` читают SQLite. Для `build` ключ нужен в окружении.

```powershell
.\.venv\Scripts\python.exe -B -m indexing.cli inspect
.\.venv\Scripts\python.exe -B -m indexing.cli build --data-dir data
.\.venv\Scripts\python.exe -B -m indexing.cli summary --data-dir data
.\.venv\Scripts\python.exe -B -m indexing.cli export --data-dir data --output indexing-export.json
```

Экспорт содержит снимок документов, обе стратегии с текстом и embedding чанков, сравнение, batch ledger и полноту накопленной стоимости. JSON может быть большим и содержать весь корпус; храните его локально. Таблицы SQLite `documents`, `runs`, `batches`, `chunks`, `metadata` позволяют независимо проверить данные. Ошибка нового запуска не подменяет прежнюю принятую пару. После рестарта `summary` и `export` читают сохранённый результат.

## Сохранённый помощник и проверки

Чат отвечает на вопросы о графике обычным текстом. Для исследования модель может выбирать инструменты MCP-серверов `research`, `processing` и `library`, подготовить отчёт, сохранить и проверить чтением. Композиция одного источника, поиск и суточные сводки остаются самостоятельными возможностями. Конфигурация чата, политики и тарифы находятся в `agent/config.toml`; панель «Расходы» показывает фактические input/output/total tokens каждого вызова и стоимость чата. Журнал embeddings на странице индексации относится к отдельным запросам и хранится в `indexing.sqlite3`.

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests_indexing -v
.\.venv\Scripts\python.exe -B -m pytest -q tests
```

Автоматические проверки используют управляемые ответы HTTP-транспорта и проверяют контракты и интерфейс. Они не измеряют качество реальных ответов модели.

## Результат реального запуска 03.10.2026

Корпус: 51 уникальный документ, 332488 символов, 6200 строк (6138 строк Python), 184.72 условной страницы. Оба индекса построены реальным OpenAI text-embedding-3-small, по 1536 измерений на каждый из 742 чанков. 47 batch-запросов сообщили 171012 input/total tokens; output не применяется. Общий расчётный расход $0.00342024, все usage известны.

| Метрика | Fixed-size | Structural |
| --- | ---: | ---: |
| Чанки | 222 | 520 |
| Медиана символов | 1800.0 | 401.0 |
| Пересекают несколько разделов | 158 | 0 |
| Fallback-чанки | 0 | 113 |
| Индексировано символов | 363268 | 345088 |
| Input tokens | 87773 | 83239 |
| Стоимость, USD | 0.00175546 | 0.00166478 |

Structural здесь сохраняет границы разделов: 0 смешанных чанков против 158 у fixed. Он создал больше небольших чанков (медиана 401 против 1800), но отправил меньше повторяющегося текста: коэффициент 1.038 против 1.093. Расход снизился примерно на 5.17%, время выросло с 12.67 до 19.84 с. 113 fallback-чанков относятся к разделам, превышающим лимит размера. Эти измерения описывают структуру и стоимость; качество retrieval этим запуском не оценивалось.
