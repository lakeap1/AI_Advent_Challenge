# День 25 — чат с RAG и памятью диалога

Это самостоятельная версия помощника по компьютерной графике и арту. Обычный чат сохраняет историю и условия пользователя, перед каждым ответом подбирает фрагменты локальной базы и показывает фактически использованные источники. Цель, уточнения, ограничения и термины относятся к выбранному диалогу и ветке; после повторного открытия они восстанавливаются. При отсутствии подходящего фрагмента помощник отвечает «Не знаю» и показывает пустой список источников. Формальная задача с этапами остаётся доступной при явном создании новой задачи.

Для тематических примеров включены русские адаптации текстовых разделов Blender Manual 4.4 о normal maps, запекании, свете и управлении цветом. Каждый файл указывает оригинальный URL, автора, версию и лицензию CC BY-SA 4.0. База также содержит документацию и исходники самого приложения; источник ответа следует проверять по показанным полным фрагментам, а не по одному названию.

## Запуск

Нужны Python 3.11+, доступ к OpenAI API и зависимости из `requirements.txt`. Команды ниже выполняются из `week_5/task_5` в PowerShell. Создайте в этой папке локальный `.env` с `OPENAI_API_KEY=<ваш ключ>`; не добавляйте его в Git. Установите зависимости в отдельное окружение:

```text
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Сначала проверьте состав корпуса, затем постройте локальный индекс. Сам `indexing.cli` не загружает `.env`, поэтому команда `build` ниже явно загружает его через `python-dotenv`. Индексация обращается к API embeddings и расходует токены. Повторный `build` использует совместимый готовый индекс; `--force` нужен только при осознанной перестройке.

```text
.venv\Scripts\python.exe -B -m indexing.cli inspect
.venv\Scripts\python.exe -B -c "from dotenv import load_dotenv; load_dotenv('.env'); from indexing.cli import main; raise SystemExit(main(['build', '--data-dir', 'data']))"
.venv\Scripts\python.exe -B -m indexing.cli summary --data-dir data
```

После успешной индексации запустите приложение на отдельном локальном порту 5025:

```text
$env:CHAT_DATA_DIR = (Join-Path (Get-Location) 'data')
.venv\Scripts\python.exe -B -m flask --app app:create_app run --host 127.0.0.1 --port 5025 --no-reload
```

Откройте `http://127.0.0.1:5025/`. Например, можно спросить: «Хочу разобраться с normal map в Blender 4.4. Моя цель — добавить мелкие детали без изменения геометрии. Что делает узел Normal Map?» Затем уточнить UVMap или Strength и позже спросить «Вернись к моей цели». Справа отображается сохранённая цель и действующие условия. Под каждым ответом раскрываются полные использованные фрагменты с документом, разделом и ID чанка. Счётчик токенов и стоимости находится в панели «Расходы».

## Проверка двух длинных диалогов

`evaluation/conversation_scenarios.json` содержит два фиксированных сценария по 12 пользовательских вопросов. Проверочный CLI создаёт отдельное локальное рабочее пространство рядом с новым выходным JSON, копирует туда проверенный индекс, выполняет каждый вопрос один раз через те же маршруты приложения и после каждого хода атомарно сохраняет полный снимок: исходный вопрос, ответ, состояние до и после, retrieval, выбранные и использованные фрагменты, запросы с политиками/usage/стоимостью и отправленные payload без заголовка авторизации. После каждого сценария он проверяет восстановление диалога, а в конце — изоляцию первого от второго. Файл результата не перезаписывается: для нового прогона задайте новое имя `--output`.

```text
.venv\Scripts\python.exe -B scripts\evaluate_conversation.py --data-dir data --output data\conversation-evaluation.json --env-file .env --scenarios evaluation\conversation_scenarios.json
```

Эта команда делает реальные платные API-вызовы. Статус `complete_structural` означает, что прошли проверки формы ответа, источников и текущих значений памяти. Он не доказывает смысловую правильность: ответы и полные фрагменты нужно отдельно прочитать и сопоставить с ожидаемыми фактами каждого хода. Пустой ответ, отказ на отвечаемом вопросе или отсутствие использованных источников отмечаются как сбой; скрытого повторного вызова нет.

## Локальные тесты и ограничения

```text
.venv\Scripts\python.exe -B -m pytest -p no:cacheprovider tests tests_conversation tests_evaluation tests_indexing tests_rag -q
$env:RUN_UI_TESTS = '1'
.venv\Scripts\python.exe -B -m pytest -p no:cacheprovider tests\test_chat_ui.py -q
```

Для браузерных тестов нужен установленный Playwright и Chromium. Эти тесты используют управляемые ответы провайдера, но реальные Flask, SQLite и DOM; они не являются проверкой качества ответов реальной модели.

Источники ограничены выбранным локальным корпусом и документацией Blender 4.4. Ассистент не видит сцену, файлы или рендер пользователя и не может подтвердить результат настройки без их фактической проверки. Подготовка памяти, embedding, фильтрация и генерация — отдельные учитываемые вызовы. При сбое output policy ответ не публикуется, но доступные токены и стоимость уже выполненных стадий сохраняются; неизвестная стоимость помечается неизвестной.
