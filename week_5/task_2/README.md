# День 22 — RAG в помощнике по компьютерной графике и арту

Приложение развивает единого тематического агента: к обычному чату добавлен поиск по локальной базе. В режиме RAG вопрос преобразуется в embedding, поиск выбирает релевантные чанки, проверенные фрагменты объединяются с вопросом и текущим контекстом, затем агент обращается к LLM. Переключатель «RAG · поиск в локальной базе» находится рядом с полем сообщения.

Оба режима сохраняют историю, профиль, память, состояние задачи и MCP-возможности помощника. База дня 21 содержит README и код предыдущей версии агента. Поэтому контрольные вопросы проверяют факты проекта; база не является полной энциклопедией компьютерной графики.

## Запуск

Нужен Python 3.11+ и ключ OpenAI. Из папки задания:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
# Запишите OPENAI_API_KEY в локальный .env.
.venv\Scripts\python.exe app.py
```

Откройте http://127.0.0.1:5022/ — основной чат. Настройки агента находятся в agent/config.toml, параметры поиска и embeddings — в rag/config.toml. По умолчанию данные сохраняются в data/; CHAT_DATA_DIR задаёт другой локальный каталог. Приложение работает с собственным кодом, без импортов из предыдущих заданий.

Для RAG нужен совместимый индекс. На экране /indexing можно построить индекс через embedding API. Построение оплачивается отдельно. Существующий индекс дня 21 можно перенести:

```powershell
.venv\Scripts\python.exe -B -m rag.cli import-index --source ../task_1/data/indexing.sqlite3 --data-dir data
```

Импорт проверяет снимок и не заменяет существующий файл. Перед генерацией проверяются соответствие корпуса, модели, размерности, метаданных и локаторов, точные срезы источников, форма векторов, конечность их значений и ненулевая норма. Несовместимый индекс останавливает RAG до нового embedding. Произвольную согласованную замену векторов эта схема не обнаруживает.

## Использование

В обычном чате задавайте содержательные вопросы о графике, материалах, свете, моделировании и художественной работе. RAG добавляет документы локального проекта к ответу. Под ответом доступны фактически использованные чанки с путями и строками; расходы и источники сохраняются после обновления страницы.

В левом списке агентов выберите «Сравнение RAG». Это отдельная вкладка того же приложения, рядом со «Сводками о графике». Обычный чат сохраняет свой переключатель RAG. Во вкладке сравнения слева расположен чат «С RAG», справа — «Без RAG»; у каждой стороны своя прокрутка и история сообщений. На узком экране переключатель показывает одну сторону, сохраняя обе истории.

Создайте новый прогон, вставьте следующий контрольный вопрос или введите его точный текст и нажмите «Получить два ответа». Один вопрос появляется в обеих лентах. Каждая сторона показывает собственный полный ответ и фактические расходы; у RAG доступны реально переданные фрагменты с файлом и строками. Ожидания и независимая оценка раскрываются в отдельном блоке разбора. Они не мешают чтению ответов.

Все десять вопросов проходят последовательно. Выбор сохранённого прогона, просмотр источников, переход между вкладками и перезагрузка страницы не запускают модель. Оценка появляется после независимого разбора сохранённых ответов и локального импорта; до этого интерфейс честно показывает ожидание оценки.

Вопросы и ожидания зафиксированы в evaluation/questions.json. Ожидания используются для проверки и не передаются модели, генерирующей ответы. Для каждой пары создаются две свежие внутренние области того же production-агента с одинаковым начальным профилем, состоянием задачи и инвариантами. История и изменяемая память исключены из обеих версий. Внешние инструменты отключены для обеих версий контролируемого сравнения, чтобы они не добавляли второй источник знаний. Обычный чат продолжает использовать свои инструменты.

Вызовы извлечения памяти выполняются после генерации и входят в расходы пары; их результат не переносится к следующему контрольному вопросу. Повтор уже зарегистрированного вопроса возвращает сохранённый результат без нового API-вызова. После прерывания статус и все доступные расходы сохраняются; автоматического повтора нет. Незавершённый или отклонённый ответ не считается успешным сравнением. Видимые карточки принадлежат текущим профилю, задаче, диалогу и ветке; сводка расходов диалога включает его выполненные вызовы один раз.

## Независимая оценка

До импорта содержательной оценки показывается pending. Сначала экспортируйте полный завершённый прогон, затем проверьте реальные ответы по ожидаемым фактам и точному отправленному контексту. При остановленном веб-сервере:

```powershell
.venv\Scripts\python.exe -B -m rag.chat_evaluation_cli --data-dir data --profile-id 1 export RUN_ID evidence.json
.venv\Scripts\python.exe -B -m rag.chat_evaluation_cli --data-dir data --profile-id 1 import assessment.json
```

Замените профиль и RUN_ID своими значениями. Файл оценки содержит run_id, evidence_sha256, данные reviewer и десять questions. Для каждого атомарного факта указываются правильность plain/rag, пояснения, подтверждение RAG и метки фактических чанков. Для каждого ответа указываются полнота, неподтверждённые утверждения и корректность отказа; отдельно оценивается достаточность контекста. Формат и проверки реализованы в rag/chat_evaluation.py. Импорт отвергает устаревший хеш, неполный разбор, неизвестные метки и противоречивую оценку полноты. Перезапустите приложение после импорта.

Полный ответ требует всех ожидаемых фактов и отсутствия неподтверждённых утверждений. Для RAG требуется также опора на фактически переданный контекст. Десятый вопрос проверяет корректный отказ: конкретный SHA-256 результата отсутствует в базе. Проверка структуры оценки не доказывает её смысловую правильность; содержательную оценку выполняет независимый проверяющий.

## Результат нового прогона двух чатов

4 октября 2026 года выполнено сравнение на десяти вопросах и двадцати реальных ответах. Ответы оценены по полной базе, а поддержка RAG — по точным переданным чанкам. Строгий критерий атомарного факта требует всего ожидания: например, «до трёх» не получает зачёт за «от одного до трёх».

| Показатель | Без RAG | С RAG |
| --- | ---: | ---: |
| Верные ожидаемые факты по полной базе | 5/26 | 15/26 |
| Верные факты с подтверждением переданными чанками | — | 13/26 |
| Полные ответы по всем критериям | 1/10 | 4/10 |
| Корректный отказ на вопрос без ответа в базе | Да | Да |
| Расчёт расходов всех стадий режима, USD | 0.002195805 | 0.003699335 |

Все 50 API-стадий учтены: двадцать генераций ответов, двадцать последующих извлечений памяти и десять query embeddings. Провайдер сообщил 84 370 входных, 3573 выходных и 87 943 суммарных токенов; стоимость по сохранённым тарифам составляет $0.005895140. Неизвестных расходов в этом завершённом прогоне нет. Эти суммы не включают прежнее построение индекса и независимую оценку ответов. Неуспешная первая попытка из-за соединения сохранена отдельным прогоном с неизвестной стоимостью; она не объявлена нулевой и не включена в точную сумму завершённого прогона.

| Вопрос | Верные факты без RAG | Верные факты с RAG | Подтверждены чанками | Полный ответ без / с RAG |

| Q05 · Идентификаторы доступа и HTTP-ответ | 0/2 | 0/2 | 0/2 | Нет / Нет |
| Q06 · Reasoning и неизвестная стоимость | 2/3 | 3/3 | 3/3 | Нет / Да |
| Q07 · Недоступный сервер сводок | 0/2 | 2/2 | 2/2 | Нет / Да |
| Q08 · Перезапуск оркестрации | 0/2 | 1/2 | 0/2 | Нет / Нет |

| Q10 · Отсутствующий конкретный SHA-256 | 1/1 | 1/1 | 1/1 | Да / Да |

RAG помог перечислить MCP-серверы, объяснить учёт расходов и восстановление локальной истории сводок. Для Q02 и Q05 нужные участки кода не попали в контекст. В Q03 проверка полей результата чтения подменила проверку файловых байтов; Q04 не перечислил все источники. В Q08 модель использовала восстановление сервера сводок как описание оркестрации. В Q09 факты верны по полной базе, но сохранность результата оркестрации не подтверждается переданными чанками. Поэтому правильность факта и подтверждение подходящим источником оцениваются отдельно.

Это один небольшой прогон по базе проекта с независимой оценкой. Он не измеряет общую точность модели и не гарантирует превосходство RAG. Корпус, вопросы, ожидания, параметры поиска и модель генерации между двумя режимами не менялись. Набор вопросов с ожиданиями и кандидатами источников находится в `evaluation/questions.json`.

## Поиск, политики и расходы

Стек: Python, Flask, SQLite, OpenAI Responses API и Embeddings API. Генерация основного агента использует gpt-6-luna; embedding — text-embedding-3-small, 1536 измерений. Поиск использует structural-чанки и cosine similarity, выбирает до шести кандидатов. Контекст ограничен бюджетом 6000 по методу utf8_bytes_upper_bound; может быть передано меньше чанков. Source score означает близость векторов, а не вероятность правильного ответа. Reranking в этом задании отсутствует.

Основной чат использует собственные input/output policy агента. Вход проверяется до API, ответ — после вызова. Отклонение ответа останавливает обработку без скрытого повторного запроса. API получает инструкцию отвечать обычным текстом без Markdown. Программные проверки статуса, структуры и меток источников не являются автоматической проверкой истинности.

Для каждого выполненного вызова сохраняются фактические input/output/total tokens, cached/reasoning при наличии, тариф, его источник, модель, результаты политик и стоимость USD. Reasoning уже входит в output и не оплачивается второй раз. Неизвестные usage или стоимость обозначаются как неизвестные; при неполных данных показывается известная часть суммы с отметкой неполноты. Сохраняются расходы отклонённых и прерванных вызовов, если доступны данные провайдера.

Для воспроизводимости контрольного разбора приложение локально сохраняет ответы, фактические API-payload и чанки. Это локальное приложение без механизма аутентификации; идентификаторы профилей и проверка текущей области ограничивают рабочий контекст, но не заменяют защиту многопользовательского сервиса.

## Проверки и состав

```powershell
.venv\Scripts\python.exe -B -m pytest -p no:cacheprovider -q tests_rag tests_indexing tests
npm install --no-save playwright
npx playwright install chromium
node scripts/check-chat-rag-browser.cjs
node scripts/check-chat-evaluation-browser.cjs
```

Браузерные проверки требуют Playwright и Chromium. Они используют синтетические HTTP-ответы, проверяют интерфейс, изоляцию, расходы, восстановление и ошибки; качество реальной модели ими не измеряется.

Основные компоненты: app.py и agent/ — агент и HTTP-приложение; indexing/ — индекс; rag/chat.py — RAG основного чата; rag/chat_evaluation.py и маршруты — контролируемый разбор; static/ и templates/ — интерфейс; evaluation/questions.json — контрольный набор; tests/, tests_indexing/ и tests_rag/ — поведенческие проверки. Прежний отдельный /rag сохраняется для совместимости; сравнение текущего агента доступно отдельной вкладкой левого списка агентов в том же приложении.
