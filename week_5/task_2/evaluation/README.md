# Контрольный набор дня22

questions.json фиксирует 10 вопросов до первого запроса генерации. База — исходники и README помощника, сохранённые днём21. Эталонные ожидания и локаторы проверены по исходникам. Они не передаются LLM.

Сравниваются два чистых запроса одной модели gpt-6-luna/none с общими инструкциями и лимитом ответа. В режиме plain нет корпуса, retrieval, MCP, памяти или истории; rag добавляет тексты выбранных structural чанков. Top-k=6. При недоступном кеше токенизатора контекст ограничен6000 UTF-8 байтами как консервативной верхней границей6000токенов BPE; фактическое количество токенов при этом не заявляется. Метод выбран до первого live прогона и может ограничить число включённых чанков. Затраты построения индекса отделены от query/generation.

Оценка каждой пары: отдельно доля корректных атомарных фактов, полный ответ без существенного противоречия, существенные неподтверждённые утверждения, корректное признание отсутствия данных(q10), и поддержка тезисов фактически переданным контекстом. У q10 один факт: точный хеш неизвестен. Дополнительное объяснение допустимо, выдуманный хеш — провал.

Expected_sources — кандидаты на доказательные источники, альтернативные источники допустимы при подтверждении фактов. Совпадение имени файла измеряет source recall proxy, а не полное покрытие всех необходимых строк. Ключевой oracle — содержание exact retrieved chunks и исходников. Семантическую оценку выполняет независимый reviewer по заранее заданным фактам; оценки содержат причину. Reviewer может ошибаться, root проверяет ключевые примеры. Это agent review, не пользовательская человеческая оценка и не автоматическое доказательство истинности.

Все фактические ответы, выбранные чанки, usage/стоимость и оценки доступны в сохранённом локальном отчёте. Один парный прогон 10 вопросов описывает данную выборку; статистическая гарантия и качество на всей предметной области из него не следуют. Если RAG пропустит нужный чанк, это фиксируется как ошибка поиска; ожидания после прогона не переписываются.
