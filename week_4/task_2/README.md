# День 17 — источники знаний через собственный MCP

Помощник объясняет компьютерную игровую графику на практических примерах: normal mapping, PBR, UV, свет и рендеринг. Он получает определения из Wikipedia и вопросы с ответами из Stack Exchange, затем использует найденный текст в ответе модели. Карточки источников позволяют открыть оригинал и прочитать полученный фрагмент.

Приложение развивает предыдущего тематического агента: сохранены профили, три стратегии контекста, память, этапы учебной задачи, инварианты, политики и учёт расходов. Код находится целиком в этой папке, импортов из соседних заданий нет. Стек: Python 3.11+, Flask, SQLite, Responses API, MCP SDK 2.2.0.

## Как проходит запрос

Вопрос и выбранные источники → локальный агент → MCP-клиент → SSH-туннель → собственный MCP-сервер на капсуле → Wikipedia / Stack Exchange → ограниченные фрагменты → основной запрос модели → ответ и карточки источников.

Инструменты выбирает логика приложения по переключателю пользователя. Модель не планирует вызовы самостоятельно. Внешние API вызываются только сервером; приложение не обращается к ним в обход MCP. MCP-сервер не использует LLM и не получает её ключ.

## Локальный запуск

Из папки задания:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполните OPENAI_API_KEY в .env. KNOWLEDGE_MCP_URL по умолчанию указывает на http://127.0.0.1:8017/mcp — локальный конец SSH-туннеля.

```powershell
.\.venv\Scripts\python.exe app.py
```

Откройте http://127.0.0.1:5017. Без ключа доступны локальные настройки, но модель не ответит. Без туннеля можно работать в режиме «Без поиска»; выбранный недоступный источник вызовет явную ошибку.

Модель, политики, тариф и его источник находятся в agent/config.toml. По умолчанию используется gpt-5.6-luna, reasoning none. После изменения конфигурации или окружения перезапустите приложение. Данные сохраняются в data/; каталог можно переопределить через CHAT_DATA_DIR. Приложение рассчитано на одного локального оператора; профили не заменяют авторизацию. Локальные SQLite-базы не зашифрованы.

## Сервер на капсуле

Передайте на Linux-сервер только каталог knowledge_server. Не копируйте .env, локальные базы или закрытый ключ SSH. Пример для каталога ~/ai-advent-day17:

```sh
mkdir -p ~/ai-advent-day17
cd ~/ai-advent-day17
python3 -m venv .venv
.venv/bin/python -m pip install -r knowledge_server/requirements.txt
.venv/bin/python -m knowledge_server.server
```

Сервер слушает 127.0.0.1:8017, MCP endpoint — /mcp. Для постоянной работы используйте пользовательский systemd-сервис; пример unit-файла находится в deploy/ai-advent-day17.service. Скопируйте его в ~/.config/systemd/user/, затем:

```sh
systemctl --user daemon-reload
systemctl --user enable --now ai-advent-day17.service
loginctl enable-linger "$USER"
systemctl --user status ai-advent-day17.service
```

Для enable-linger могут потребоваться права администратора. Этот режим позволяет сервису продолжать работу после выхода из SSH и запускаться после перезагрузки сервера.

На локальном компьютере откройте отдельный терминал с туннелем, заменив адрес и путь к вашему ключу:

```powershell
ssh -N -L 127.0.0.1:8017:127.0.0.1:8017 -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o StrictHostKeyChecking=yes -i <путь-к-ключу> <пользователь>@<адрес-капсулы>
```

Ключ хоста должен быть заранее проверен и сохранён в known_hosts. Туннель нужен на всё время работы с источниками. Публичный порт MCP открывать не требуется; доступ защищён SSH. Сам сервер предназначен для доверенного локального доступа и не реализует публичную авторизацию.

## Инструменты

| Инструмент | Параметры | Результат |
|---|---|---|
| lookup_wikipedia | query: непустая строка до 256 символов; language: en или ru, по умолчанию en; limit: 1–3, по умолчанию 3 | Вводные фрагменты статей и ссылки |
| search_stackexchange | query: непустая строка до 256 символов; community: blender, computergraphics или gamedev, по умолчанию blender; limit: 1–3, по умолчанию 3 | Вопросы с текстом ответов, ссылками, авторами, датами и рейтингом |

Успех возвращается как structured JSON: provider, query, sources, metadata. Ошибки параметров, API и MCP не маскируются под успешную выдачу. Используются публичные операции чтения; для этого сценария отдельные ключи Wikipedia/Stack Exchange не нужны. Действуют квоты провайдеров. Сервер ограничивает время и объём ответа и соблюдает Stack Exchange backoff без скрытых повторов.

Официальные описания: [MediaWiki Search](https://www.mediawiki.org/wiki/API:Search), [Stack Exchange API](https://api.stackexchange.com/docs), [ограничения Stack Exchange](https://api.stackexchange.com/docs/throttle).

## Использование

Слева находится список диалогов и кнопка «Новый чат», в центре — переписка, справа — контекст текущей задачи. Контекст можно скрыть. На узком экране список открывается кнопкой «Чаты».

1. Откройте верхнюю панель «Источники» или кнопку источников возле поля ввода. Выберите «Wikipedia + Stack Exchange» либо один источник. Укажите короткую тему, например normal map baking seams. В необязательном поле темы Wikipedia можно задать общее понятие normal mapping; при пустом поле используется общая тема. Для Stack Exchange обычно лучше английская формулировка; сам вопрос можно задавать по-русски.
2. Опишите учебную цель. Существующий процесс сначала составляет план с критерием проверки; утвердите его отдельным сообщением, чтобы перейти к выполнению.
3. Попросите объяснение на конкретном примере. Источники для каждого отправленного вопроса выбираются явно. Например: объяснить, почему цветовой разрыв tangent-space normal map на UV-шве не обязательно означает видимый шов на модели.
4. В панели «Источники» посмотрите «Источники ответов»: ссылка и полученный текст отделены от интерпретации модели. Результат и связь с запросом сохраняются после перезагрузки страницы.

Enter отправляет сообщение, Shift + Enter добавляет строку. Панели закрываются кнопкой × или Escape; закрытие не сбрасывает черновик настроек. «Задача» открывает план, критерии, состояние и паузу; «Правила задачи» — обязательные ограничения; «Расходы» — журнал и трассу запросов. «Ветки» доступны для диалогов, созданных в режиме «Ветвление».

Пустой поиск обозначается явно. При ошибке выбранного источника основная генерация останавливается, ошибка сохраняется. Для продолжения измените тему/источник или исправьте соединение и отправьте новый запрос самостоятельно.

## Память, политики и расходы

Профиль открывается кнопкой слева внизу. В нём находятся стиль, формат и личные ограничения, переключение и создание профилей. Персонализация передаётся каждому ответу и отделена от обязательных правил задачи. Пауза и завершение блокируют новые вопросы.

Все три памяти работают автоматически: краткосрочная использует историю текущего диалога согласно его стратегии; рабочая хранит условия текущей задачи и доступна её диалогам; долговременная хранит устойчивые сведения пользователя или проекта. Новая задача начинает пустую рабочую память, сохраняя доступные долговременные сведения. Профили изолированы друг от друга.

Справа можно посмотреть краткосрочную и рабочую память без ручного редактирования слоёв. В профиле раздел «Что агент помнит» показывает долговременные справочные записи пользователя и текущего проекта. «Забыть» исключает запись из будущего контекста; её исторические версии остаются для трассы прежних запросов. Персонализация изменяется только собственной формой, а не удалением справочных записей. Для проверки реально переданного контекста используйте «Состав запроса» возле поля ввода или трассу в расходах.

Память и история отделены от источников: внешние фрагменты передаются только в основной LLM-запрос как недоверенная справка, не как системные команды или доказательства выполнения упражнения.

До поиска выполняются input policy и, если заданы инварианты, их смысловая проверка моделью. Если после этой платной проверки поиск завершится ошибкой, её расход сохранится. Output policy и проверки состояния остаются обязательными. Отклонённый ответ не показывается как успешный; скрытого повторного вызова нет. Модельная проверка смысла может ошибаться.

Журнал показывает фактические input_tokens, output_tokens, total_tokens каждого LLM-вызова, стоимость USD и сумму диалога, включая проверки и извлечение памяти. Cached input и reasoning учитываются отдельно при наличии; reasoning уже входит в output. Неизвестный расход не считается нулевым, неполнота суммы обозначается. MCP-запросы хранятся отдельно и не изображаются как LLM-вызовы с нулевыми токенами.

Обычный ответ запрашивается текстом без Markdown, если пользователь явно не выбрал другой формат. Программные проверки не гарантируют истинность объяснений. Старые ответы Stack Exchange могут зависеть от версии редактора; рейтинг не доказывает правильность. Wikipedia и форумы не заменяют документацию движка. Изображения из вопросов не анализируются: агент получает только текст и не проверяет ваши файлы или сцену.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты с подставными транспортами проверяют контракт провайдеров, ошибки и backoff, порядок retrieval/policy/LLM, сохранение источников и расходов, а также прежние профили, память и переходы этапов. Они не измеряют качество реальной смысловой оценки модели. Реальную доступность сервера и обоих API можно проверить отдельно:

```powershell
.\.venv\Scripts\python.exe check_mcp.py
```

Этот диагностический скрипт выполняет настоящее MCP-соединение, tools/list и по одному tools/call к каждому источнику; LLM не вызывается.

Необязательные браузерные тесты проверяют интерфейс через локальный Flask, временную базу и подставные модель и поиск. Для них дополнительно нужны Python-пакет Playwright и его Chromium:

```powershell
.\.venv\Scripts\python.exe -m pip install playwright
.\.venv\Scripts\python.exe -m playwright install chromium
$env:RUN_UI_TESTS = '1'
.\.venv\Scripts\python.exe -m pytest -q tests/test_chat_ui.py
Remove-Item Env:RUN_UI_TESTS
```
