# День 19 — автоматическая композиция MCP-инструментов

Помощник по компьютерной графике и арту выбирает инструменты и источник по обычному вопросу и доступному контексту диалога. Для просьбы подготовить обзор, отчёт или материал для дальнейшего использования доступна цепочка из трёх MCP-инструментов: получение → обработка → сохранение. Вручную выбирать MCP, режим, источник или вводить английскую поисковую тему не требуется.

Приложение продолжает агента на Python/Flask: общий чат, автоматический поиск Wikipedia/Stack Exchange, профили, память, стратегии контекста, задачи, инварианты и ветки. Сохранён чат «Сводки о графике» с выбором сохранённой сводки и серверным расписанием. Исходники самостоятельны: импортов соседних заданий нет, локальные базы предыдущих заданий автоматически не переносятся.

## Настройка и запуск

Python 3.11+, интернет, ключ OpenAI с доступом к gpt-5.6-luna. Из папки задания:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

В локальном `.env` задайте `OPENAI_API_KEY`. Не перезаписывайте уже настроенный файл.

```powershell
.\.venv\Scripts\python.exe app.py
```

Откройте http://127.0.0.1:5019. Модель, reasoning `none`, service tier `default`, лимиты и тариф находятся в `agent/config.toml`. Провайдер — OpenAI Responses API. Новый сервер композиции запускается автоматически дочерним процессом через stdio; отдельный порт и капсула для него не нужны. Первый подсчёт контекста может скачать словарь tiktoken в локальный кеш.

## Использование

Выберите обычный диалог, напишите запрос и отправьте его один раз:

```text
Подготовь краткий обзор ambient occlusion: принцип работы, применение в игровом арте и ограничения. Хочу вернуться к нему позже.
```

Модель выбирает действие `research_and_save`, подходящий источник и поисковую тему. Приложение автоматически выполняет поиск, обработку и сохранение. Этапы и фактический источник появляются в ленте. После завершения показываются ответ помощника, отдельный блок «Сохранённый разбор» с точным содержимым TXT, путь и скачивание. Краткий ответ модели может отличаться от файла; блок сохранённого разбора показывает именно записанный текст.

Можно продолжить обсуждаемую тему: «Теперь подготовь по этому краткий обзор с источниками». Слово «сохранить», формат TXT и названия инструментов не обязательны. Инструкция модели отличает готовый обзор от простого вопроса и требует учитывать просьбу не сохранять. Для обычного вопроса модель может ответить сразу либо выбрать один из инструментов поиска. Выбор вероятностный: неоднозначную тему или желаемый результат она может уточнить; безошибочное распознавание всех формулировок не гарантируется. Сохранённый разбор доступен следующему вопросу, пока связанное сообщение входит в выбранную стратегию контекста.

Для понятий и теории доступны Wikipedia на английском и русском; для практических случаев — сообщества Blender, Computer Graphics и Game Development в Stack Exchange. Модель выбирает их по содержанию вопроса. Если пользователь сам назвал источник или язык материалов, инструкция требует учитывать это предпочтение. Приложение не подменяет недоступный источник другим незаметно.

## Как устроена композиция

`Общий чат → Responses tool loop → выбранное моделью research_and_save → MCP-клиент → три MCP-инструмента → результат обратно модели и в UI`

`research_and_save` — действие приложения, предоставленное модели через function calling. Оно управляет последовательностью; это не четвёртый MCP-инструмент. Сам выбор действия делает модель, а порядок трёх зависимых шагов фиксирован кодом. Произвольное динамическое планирование здесь не реализовано и не требуется для последовательного пайплайна.

| MCP-инструмент | Вход | Результат |
|---|---|---|
| `search_graphics` | run_id, question, query, source | `Materials`: вопрос, тема, source/provider, до трёх фрагментов с title/url/excerpt/author/date |
| `summarize_graphics` | фактический объект materials первого шага | `Summary`: текст обработки, те же источники, готовый content с атрибуцией, SHA-256 |
| `save_summary` | фактический объект summary второго шага | `Saved`: имя TXT, точный content, размер и SHA-256 |

Код выбора и продолжения — `agent/tool_loop.py`, адаптер — `agent/composition_action.py`, порядок MCP — `agent/composition.py`. Регистрация отдельных MCP-инструментов — `composition/server.py`, бизнес-обработка — `composition/service.py`, Pydantic-контракты — `composition/contracts.py`.

Клиент действительно запускает отдельный процесс, устанавливает сессию MCP SDK 2.2.0, выполняет tools/list и tools/call. `source` имеет пять допустимых значений: `wikipedia_en`, `wikipedia_ru`, `blender`, `computergraphics`, `gamedev`. Это технический параметр модели, не поле формы пользователя. Общие обработка и сохранение работают для всех источников. Сервер сверяет выбранный source с запуском, ссылки — с источником, вход второго инструмента — с сохранённым результатом первого, вход третьего — с принятым результатом второго. Клиент проверяет схемы, принадлежность запуску, источники и сохранённый текст. После записи файл читается и сравнивается с ожидаемыми байтами. Результат возвращается модели как function_call_output.

За пользовательскую отправку разрешена одна композиция. Общий модельный цикл ограничен четырьмя шагами и тремя выбранными действиями; композиция внутри одного действия содержит три MCP-вызова. При отказе промежуточного инструмента зависимые шаги прекращаются. Автоматических повторов композиции и скрытого исправления отклонённой сводки нет.

## Источник и ограничения

- Реальные вводные тексты статей Wikipedia или ответы выбранного сообщества Stack Exchange через публичные API, не mock. До трёх фрагментов по 1200 символов; изображения, вложения и полные статьи/обсуждения не анализируются. Это ограниченная подборка, а не полный обзор интернета.
- Для Stack Exchange модель формирует короткую английскую тему; для Wikipedia — тему на выбранном языке. Итог запрашивается на русском. Пустая выдача, неверные материалы или недоступность источника останавливают композицию.
- Модель не осматривает ассет и не проверяет результат рекомендаций. Ссылки, авторы и даты сохраняются для проверки источников.
- Системные инструкции требуют обычный текст без Markdown. Программная output policy проверяет завершённость, структуру, отсутствие отказа и непустой текст, но не доказывает истинность советов и не удаляет Markdown принудительно.

## Политики, история и расходы

Input/output policy остаются внутри агента. Неверный вход останавливается до LLM. Отклонённая обработка не передаётся инструменту сохранения. При активных инвариантах задачи обработанный текст дополнительно проверяется до записи файла. Обычный финальный ответ проходит прежние проверки задачи и памяти.

Запись файла и последующий финальный ответ — разные результаты. Если файл уже успешно сохранён, а последующий ответ модели отклонён, файл остаётся результатом выполненных инструментов; ошибка ответа показывается отдельно. Приложение не выдаёт такой ответ как принятый. Все уже выполненные вызовы входят в расходы.

Панель «Расходы» показывает фактические input/output/total tokens, cached input и reasoning при наличии, стоимость каждого вызова и накопленную сумму чата. Учитываются выбор инструментов, обработка материалов, финальный ответ, проверки и извлечение памяти. Reasoning уже входит в output и повторно не оплачивается. Неизвестные usage/стоимость обозначаются неизвестными, сумма — неполной. MCP-вызов сам по себе не равен LLM-вызову.

Тариф, модель, tier, источник и дата проверки сохранены в конфигурации; расчёт по этому тарифу не является счётом провайдера. Журнал обработки импортируется ровно один раз, без повторного сообщения пользователя и двойного расхода. Профиль, диалог и ветка фиксируются при запуске. Обновление страницы не повторяет запрос.

`data/composition.sqlite3` хранит ход, материалы, результаты и usage. Файлы: `data/composition/results/<run_id>.txt`. Имя генерирует приложение, произвольный путь не принимается; используется эксклюзивное создание без перезаписи и проверка границ каталога. `CHAT_DATA_DIR` меняет корень локальных данных. Данные, ключи и файлы результатов исключены из Git.

Запускайте один экземпляр Flask на каталог данных. После рестарта незавершённые запуски помечаются прерванными, без повтора. Авария после записи, но до подтверждения может оставить файл с неуспешным статусом; такой запуск не объявляется успешным. Приложение предназначено для loopback; профили не заменяют сетевую авторизацию.

## Поиск и сводки предыдущих заданий

Обычный автоматический поиск использует `KNOWLEDGE_MCP_URL`, по умолчанию http://127.0.0.1:8017/mcp. Для локального сервера:

```powershell
.\.venv\Scripts\python.exe -m knowledge_server.server
```

«Сводки о графике» слева открывает обсуждение выбранного сохранённого снимка. Источники — Computer Graphics, Graphic Design и Blender Stack Exchange, последние сутки, до 100 вопросов каждого сообщества. Новые сводки не меняют снимок уже начатого обсуждения. При недоступном сервере доступна локальная история с предупреждением.

`DIGEST_MCP_URL` по умолчанию http://127.0.0.1:8018/mcp — локальный сервер или конец существующего SSH-туннеля к капсуле. Сервер запускается командой `python -m digest_server.server`. Для удалённого размещения сохранены `deploy/ai-advent-day18.service` и `deploy/install-cron.sh`. Расписание фиксировано: 00/06/12/18 часов Asia/Omsk, восстановительные cron ticks проверяют сохранённый срок. Фоновый сбор вычисляется кодом и не вызывает LLM; обсуждение снимка использует Luna. Локальный сервер требует работающего компьютера, удалённый — работающей капсулы и настроенного cron.

Независимый MCP-клиент:

```powershell
.\.venv\Scripts\python.exe scripts/digest_client.py get_digest_state
.\.venv\Scripts\python.exe scripts/digest_client.py list_digests --after 0 --limit 5
```

Композиция TXT не зависит от доступности серверов знаний и сводок: её MCP-процесс обращается к выбранному публичному API самостоятельно. Разбор сводок по этой трёхэтапной композиции не реализован; существующий чат сводок работает отдельно.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q --tb=short --basetemp=.pytest-local -p no:cacheprovider
.\.venv\Scripts\python.exe -m pytest tests/test_selected_composition.py tests/test_composition_mcp.py tests/test_composition.py -q --basetemp=.pytest-composition -p no:cacheprovider
node tests/test_composition_ui.cjs
node tests/test_digest_ui.cjs
```

Node-проверкам нужны Playwright и Chromium; `PLAYWRIGHT_NODE_MODULES` задаёт путь к модулю, `TEST_APP_URL` — адрес работающего приложения. Прежние opt-in Python UI-тесты включаются через `RUN_UI_TESTS=1`.

Тесты проверяют модельный выбор, реальный MCP stdio между процессами, порядок и равенство передаваемых объектов, остановку после отказа, защиту записи, правила перед сохранением, общий учёт без дублей, контекст следующего вопроса и сохранённые возможности. Внешние API и ответы модели в автоматических тестах контролируемые: доступность внешних сервисов проверяется отдельным живым запуском через UI и сравнением показанного текста с TXT.
