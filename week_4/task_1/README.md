# День 16 — список инструментов публичного MCP-сервера

Минимальный консольный клиент подключается к существующему публичному MCP-серверу, инициализирует сессию и получает список инструментов методом `tools/list`. Имена выводятся из ответа сервера; клиент не выполняет инструменты (`tools/call`) и не обращается к LLM.

Это самостоятельное упражнение внутри AI Advent Challenge. Интеграция с тематическим агентом и создание собственного MCP-сервера в него не входят. «Gettools» в условии означает получение списка, а не обязательный HTTP GET.

## Сервер и подход

Используется Microsoft Learn MCP Server: `https://learn.microsoft.com/api/mcp`.

- Транспорт: Streamable HTTP.
- Регистрация, API-ключ и настройки других приложений не нужны.
- Клиент: официальный Python SDK `mcp==2.2.0`.
- Последовательность: `initialize` → `notifications/initialized` → `tools/list`.
- При наличии `nextCursor` клиент получает следующие страницы списка.

Адрес и транспорт описаны в [справочнике владельца](https://learn.microsoft.com/en-us/training/support/mcp-developer-reference). Отсутствие обязательной авторизации и правила подключения указаны в [репозитории Microsoft Learn MCP Server](https://github.com/MicrosoftDocs/mcp). SDK: [Model Context Protocol Python SDK](https://github.com/modelcontextprotocol/python-sdk).

## Требования и установка

Python 3.11 или новее, доступ в интернет по HTTPS. Все команды выполняются из папки `week_4/task_1`.

Windows PowerShell:

```text
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

Linux/macOS:

```text
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

## Запуск

```text
.venv\Scripts\python -X utf8 client.py
```

В Linux/macOS замените `.venv\Scripts\python` на `.venv/bin/python`. Флаг `-X utf8` обеспечивает одинаковую кодировку русского текста, в том числе при перенаправлении вывода.

Пример реального ответа (имена, порядок и версия протокола могут измениться):

```text
Сервер: https://learn.microsoft.com/api/mcp
Транспорт: Streamable HTTP. Подключение и initialize...
MCP initialize: OK — Microsoft Learn MCP Server 1.0.0; протокол 2025-06-18
Запрос tools/list...
tools/list: OK. Получено инструментов: 3
1. microsoft_docs_search
2. microsoft_code_sample_search
3. microsoft_docs_fetch
```

Строка `initialize: OK` появляется только после успешного протокольного ответа. Строка `tools/list: OK` и имена — после получения всех страниц списка. Пустой ответ показывает количество 0. Список не хранится в коде.

Дополнительные параметры:

```text
.venv\Scripts\python -X utf8 client.py --timeout 15
.venv\Scripts\python -X utf8 client.py --json-output response.json
.venv\Scripts\python -X utf8 client.py --url https://learn.microsoft.com/api/mcp
.venv\Scripts\python -X utf8 client.py --help
```

`--timeout` ограничивает всю сетевую операцию (по умолчанию 30 секунд). `--json-output` сохраняет ответы инициализации и всех страниц, включая описания и схемы параметров; указанный файл перезаписывается. Он никогда не используется вместо нового запроса. `--url` позволяет явно выбрать другой совместимый сервер без авторизации.

При ошибке подключения, MCP-инициализации или получения списка клиент печатает причину в stderr и возвращает код 1. Ошибка аргументов возвращает 2, прерывание пользователем — 130. Если список получен, но JSON сохранить не удалось, сообщение отличает эту ошибку от сетевой. Успешное завершение возвращает 0.

## Проверка

Автономные тесты граничных случаев без сети:

```text
.venv\Scripts\python -X utf8 -m unittest -v
```

Реальная интеграционная проверка публичного сервера:

```text
.venv\Scripts\python -X utf8 check_live.py
```

Проверка использует настоящий HTTP-транспорт SDK: наблюдает исходящие JSON-RPC сообщения, разрешает только `initialize`, `notifications/initialized`, `tools/list` и сравнивает выведенные имена с полученным ответом. Требует непустого списка от публичного сервера и завершается ошибкой при нарушении условий. Обычный HTTP 200 не считается достаточным доказательством. Автономные тесты используют тестовые ответы только для граничных случаев; они не заменяют реальный запуск.

## Ограничения

- Доступность внешнего сервера, список инструментов, порядок и их схемы могут меняться. При недоступности клиент сообщает ошибку; автоматической подмены источника нет.
- Поддерживается Streamable HTTP без настройки авторизации. Старый SSE-транспорт и stdio в это упражнение не входят.
- В консоли показываются только имена. Получение описания инструмента не означает его выполнение.
- Нет запросов к модели, поэтому токены и стоимость LLM неприменимы.

## Файлы

- `client.py` — подключение, MCP-инициализация, список, вывод и обработка ошибок.
- `requirements.txt` — версия официального SDK.
- `test_client.py` — автономные проверки пагинации, ошибок и аргументов.
- `check_live.py` — проверка реального протокольного обмена и соответствия вывода ответу.
