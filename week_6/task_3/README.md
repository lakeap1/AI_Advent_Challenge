# День 28 — локальная LLM с RAG по графике и Unity

Помощник ищет сведения в локальном корпусе, передаёт найденные фрагменты локальной Qwen через Ollama и показывает ответ вместе с полными источниками. Для сравнения тот же вопрос, системная инструкция и контекст отправляются облачной модели отдельным, явно выбранным режимом. Вопросы независимы; история хранит результаты, но не становится скрытым контекстом следующего запроса.

Приложение расширяет помощника [дня 27](../task_2/README.md): использует его Flask-приложение, исходный корпус и структурное разбиение. Код дня 27 остаётся доступен по `/chat`. В индекс добавлены проверенные материалы Unity 6.0/URP о Lit, normal map, color space, data textures, light probes и SRP Batcher. Векторный индекс строится заново для `qwen3-embedding:0.6b` с размерностью 1024: существующая база заданий недели 6 не содержала совместимого готового индекса для этих весов. Исходный код и корпус лежат в папках двух заданий; содержимое `data/`, веса и записи не входят в репозиторий.

## Подготовка и запуск

Нужны Python 3.11+, Ollama и модели `qwen3-embedding:0.6b` и `qwen3.5:9b`. Установите и запустите Ollama согласно её документации. Для локального режима сервер должен слушать `127.0.0.1:11434`, а обе модели должны быть доступны в `ollama list`. Если веса уже подготовлены, повторно скачивать их не нужно.

```text
ollama pull qwen3-embedding:0.6b
ollama pull qwen3.5:9b
ollama list
```

Команды ниже выполняются из `week_6/task_3`; рядом должна оставаться папка `week_6/task_2` с исходным корпусом. Зависимости задания ссылаются на `../task_2/requirements.txt`.

```text
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe -B -m local_rag.cli build --data-dir data
.venv/Scripts/python.exe -B -m flask --app app:create_app run --host 127.0.0.1 --port 5028 --no-reload
```

Откройте `http://127.0.0.1:5028/`. Построение индекса — отдельная операция: сервер не выполняет её автоматически при открытии страницы. После изменения корпуса, модели или параметров индекса выполните `build` повторно. При запуске приложения с нестандартным каталогом данных укажите тот же путь для build и сервера через `create_app(data_dir=...)`; обычный запуск использует `data/`.

Пример содержательного вопроса: «В Unity 6 URP пластиковый материал даёт слишком резкий блик. Как изменить Smoothness и какой канал текстуры управляет этим параметром?» Для сравнения выберите режим «Сравнить две модели» и задайте вопрос о SRP Batcher из формы или `evaluation/questions.json`. Локальный режим не требует `OPENAI_API_KEY`; облачный и сравнительный режимы требуют ключ в окружении процесса сервера. Выбор облачного режима совершает оплачиваемый API-вызов.

## Поиск, политики и расходы

Поиск объединяет локальный embedding/cosine ranking и BM25 по словам, выбирает до трёх фрагментов в пределах бюджета контекста и показывает URL, раздел, файл, диапазон строк, chunk ID и полный текст каждого источника. `context_sha256` удостоверяет выбранный контекст; `request_sha256` охватывает точные вопрос, системную инструкцию и контекст. В сравнительном режиме два результата должны иметь одинаковый request hash. Хеши подтверждают идентичность входа, но не фактическую правильность ответа.

Input policy ограничивает вопрос 2000 символами и отклоняет недопустимый ввод до вызова модели. Output policy проверяет завершение, JSON-структуру, принадлежность меток источников найденному набору и длину ответа. Наличие допустимой метки не доказывает, что она подтверждает связанное утверждение: смысловая проверка остаётся отдельной ручной задачей. Сервис просит модель отвечать по-русски обычным текстом без Markdown; это инструкция модели, не принудительная очистка или смысловая проверка. Отклонённый ответ не показывается как успешный, а доступные usage и стоимость уже выполненного вызова остаются в журнале. Неизвестные usage/стоимость и незавершённые receipts блокируют дальнейшие вызовы также после перезапуска; скрытого повтора или облачного fallback нет.

В интерфейсе и SQLite сохраняются `input_tokens`, `output_tokens`, `total_tokens`, сообщённые cached/reasoning counters, политики, модель, тариф, источник и стоимость каждого API-вызова. Накопленная сумма включает отклонённые ответы. Отсутствующие данные остаются неизвестными, а известная часть неполной суммы помечается отдельно. Для локальной Ollama токенный API-тариф равен 0 USD; электричество, оборудование и прочие затраты инфраструктуры не измерены. Облачный тарифный снимок для `gpt-6-luna` standard от 2026-10-11 находится в `local_rag/config.toml`, источник — [официальная страница тарифов API](https://developers.openai.com/api/docs/pricing). Перед новым сравнением проверьте актуальность тарифа.

## Проверка и воспроизведение сравнения

Автоматические тесты используют управляемые ответы транспорта и не подменяют реальный прогон моделей:

```text
.venv/Scripts/python.exe -B -m pytest -p no:cacheprovider tests -q
```

Дополнительная проверка интерфейса использует управляемые ответы API и не вызывает модель. Установите Playwright с Chromium; при нестандартном расположении пакета задайте `PLAYWRIGHT_MODULE_PATH` путём к пакету `playwright`. Python по умолчанию берётся из `.venv` этого задания; `PYTHON` позволяет выбрать другой интерпретатор.

```text
node scripts/check-local-rag-browser.cjs
```

После подготовки настоящего индекса можно проверить локальный маршрут без облачного ключа:

```text
.venv/Scripts/python.exe -B -m scripts.check_local --data-dir data --output data/local-probe.json
```

Скрипт удаляет ключ из своего процесса, блокирует внешние DNS/socket-вызовы, проверяет блокировку отрицательным контролем и отправляет локальный вопрос через Flask test client. Он сохраняет ответ, источники, usage и число заблокированных попыток. Проверка относится к одному Python-процессу: она не отключает сеть на компьютере и не проверяет сетевую активность Ollama. Скрипт использует существующий индекс и не стирает историю или receipts.

Сравнительный прогон выполняет пять фиксированных вопросов по три раза, последовательно local → cloud. Перед каждым вызовом он учитывает уже известную стоимость серии и резервирует консервативную верхнюю оценку следующего облачного запроса относительно лимита 0.05 USD. Неизвестный расход или ошибка останавливает серию без скрытого повтора; частичный JSON остаётся на диске. Выбирайте новый путь результата, поскольку скрипт не перезаписывает прежние прогоны.

```text
.venv/Scripts/python.exe -B -m scripts.benchmark --data-dir data --output data/paired-run.json --repeats 3 --budget-usd 0.05
.venv/Scripts/python.exe -B -m scripts.benchmark --analyze data/paired-run.json --output data/paired-report.json
```

`--env-file` позволяет передать путь к локальному файлу с `OPENAI_API_KEY`, если ключ не задан в окружении. Ключ не записывается в отчёт. Анализ существующего JSON не вызывает модели и не изменяет SQLite. В отчёте отдельно указаны hit ожидаемого файла, времена генерации и всей пары, ошибки каждого провайдера, одинаковость request hash, уникальные хеши ответов, токены и известная стоимость. Keyword coverage — только грубый автоматический индикатор наличия слов; фактическую полноту и поддержку каждого пункта `expected_facts` нужно оценивать по полному ответу и источникам вручную.

Сравнение включает пять вопросов × три повтора (15 пар, 30 ответов). Ожидаемый файл найден в 15/15 парах, все 45 ожидаемых фактов присутствовали в переданном контексте, request hash совпал в 15/15 парах. Ручная оценка всех полных ответов и фактических фрагментов сохранена в [таблице по фактам](evaluation/manual_review.json). Полностью верный факт засчитывался только при передаче всех существенных частей без ошибки; частичный факт не засчитывался как полный.

| Показатель | Локальная Qwen | Облачная модель |
| --- | ---: | ---: |
| Технически успешные ответы | 15/15 | 15/15 |
| Полностью верные ожидаемые факты | 39/45 | 45/45 |
| Частичные / неверные факты | 3 / 3 | 0 / 0 |
| Ответы без неподтверждённых утверждений | 9/15 | 15/15 |
| Ответы с нерелевантными метками источников | 15/15 | 0/15 |
| Генерация, медиана (мин–макс) | 2.00 с (1.81–2.17) | 2.88 с (2.34–3.17) |
| Токенный API за серию | 0 USD | 0.0023147 USD |

Локальный ответ q1 трижды ошибочно приписал выбор альфа-канала Smoothness параметру `Workflow Mode`; фрагмент S1 указывает `Source`, и облачный ответ назвал его верно. В q4 локальный ответ трижды не сказал явно о запекании проб, поэтому этот факт частичный. В q3 локальный ответ добавил не подтверждённое переданными S2/S3 утверждение об «отображении на экране»; эта оценка не объявляет утверждение ложным вне контекста.

Медиана полной пары составила 5.95 с (5.28–7.02). Это тёплый прогон на одной машине с RTX 5070 Ti 16 GiB и фиксированным порядком local → cloud; порядок, пять тем и три повтора ограничивают переносимость сравнения скорости и качества. Первый холодный локальный вызов генерации до серии занял 15.307 с и не входит в медианы таблицы. Пять локальных формулировок повторились побайтно по три раза, а 15 облачных формулировок различались по байтам. Побайтовое совпадение или различие не равно стабильности фактов; технических отказов в этой серии не было. Локальный токенный API не тарифицируется, но стоимость инфраструктуры неизвестна.
