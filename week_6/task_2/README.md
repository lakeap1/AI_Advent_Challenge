# День 27 — локальная LLM в помощнике по графике

Продолжение готового веб-приложения дня 25. В боковой панели добавлен отдельный чат «Локальный помощник»: запросы и история передаются установленной Qwen3.5-9B через Ollama, ответы отображаются в приложении. Для этого чата не нужны OpenAI API, облачные embeddings или внешний поиск.

Исходники предыдущего помощника включены в эту папку; приложение не импортирует код из других заданий. Прежние режимы, профили, RAG, инструменты и учёт остаются в приложении. Их облачные зависимости сохраняются, поэтому для автономного сценария выбирайте именно «Локальный помощник».

## Подготовка

Нужны Python 3.11+, Ollama и предварительно скачанная модель `qwen3.5:9b`. Проверенная конфигурация использует Ollama 0.40.3 и GGUF Q4_K_M. При установленной Ollama запустите сервер с отключённым облаком:

```text
$env:OLLAMA_HOST = '127.0.0.1:11434'
$env:OLLAMA_NO_CLOUD = '1'
ollama serve
```

В другом терминале скачайте веса, если их ещё нет:

```text
ollama pull qwen3.5:9b
```

Если вы уже подготовили runtime и модель в задании 26, используйте их скрипт запуска вместо второй установки. Из корня проекта:

```text
powershell -NoProfile -ExecutionPolicy Bypass -File week_6/task_1/scripts/start-runtime.ps1
```

Если порт уже занят работающей Ollama, второй сервер запускать не нужно. Клиент обращается только к `http://127.0.0.1:11434`, отключает прокси и не следует HTTP redirect.

## Запуск приложения

Следующие команды выполняются из `week_6/task_2`:

```text
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe -B -m flask --app app:create_app run --host 127.0.0.1 --port 5027 --no-reload
```

Откройте `http://127.0.0.1:5027/`. В локальном чате можно спросить: «У пластикового материала roughness 0.23. Как получить более широкий мягкий блик?» Затем задать уточнение: «Какое исходное значение я указал?» Сохранённая история передаётся модели в следующем запросе и восстанавливается после перезапуска.

Для локального сценария `.env` и `OPENAI_API_KEY` не требуются. Облачное рабочее пространство создаётся при обращении к прежнему режиму, поэтому запуск локального чата не скачивает облачный токенизатор. Использование прежнего RAG требует его подготовки и API-ключа; инструкции и описание этих возможностей приведены в [задании 25](../../week_5/task_5/README.md).

## Конфигурация и учёт

`local_agent/config.toml` содержит параметры модели, лимиты и политики. Контекст — 8192 токена, лимит ответа — 1024, `stream=false`, `think=false`. Вход ограничен 2000 символами, полный передаваемый контекст — 16000 символами. Дополнительно применяется консервативная оценка по UTF-8 bytes с запасом на служебный шаблон и ответ; это оценка бюджета, а не фактическое число токенов. При превышении лимита приложение сообщает об этом до вызова модели; история не обрезается скрытно.

История и метаданные сохраняются в отдельной SQLite-базе внутри `data/`. Тексты хранятся как история чата; учёт расходов не создаёт дополнительной копии запросов и ответов. Для каждого вызова показываются фактические `prompt_eval_count` и `eval_count`; total — их вычисленная сумма. Если отдельные cached/reasoning-счётчики не сообщены, они остаются неизвестными.

Стоимость токенного API локальной модели — 0 USD с явным тарифом, моделью, режимом, источником и датой проверки. Затраты на электричество и оборудование не измерены. Неизвестные токены или расходы не заменяются нулём; накопленная сумма помечается неполной.

Input policy проверяет тип, пустоту и длину входа. Output policy проверяет завершение, ошибки, непустой ответ, обрезание по токенному лимиту и предел 2000 символов. Отклонённый ответ не отображается как успешный, но доступные токены и стоимость сохраняются. При неизвестном usage или прерванном запросе дальнейшие вопросы блокируются, в том числе после перезапуска. Скрытых повторов и облачного fallback нет.

Модель получает инструкцию отвечать по-русски обычным текстом без Markdown. Это инструкция, а не программная очистка разметки или проверка истинности. Локальный чат отвечает из знаний модели и переданной истории; он не использует grounded RAG и не видит ваши сцены, изображения или файлы.

## Проверки

Автоматические проверки локального сервиса и маршрутов:

```text
.venv/Scripts/python.exe -B -m pytest -p no:cacheprovider tests_local -q
```

Реальная проверка двух связанных вопросов и восстановления состояния:

```text
.venv/Scripts/python.exe -B check_local.py
```

Скрипт удаляет облачный ключ только из своего процесса и запрещает внешние socket/DNS-соединения процесса приложения, разрешая loopback. Он вызывает настоящее Flask-приложение и Ollama, сохраняет результат в `data/`. Это проверка ограниченного процесса приложения; она не отключает Интернет на компьютере и не устанавливает firewall для процесса Ollama.

Для запуска того же приложения с этой проверочной сетевой границей:

```text
.venv/Scripts/python.exe -B check_local.py --serve --port 5027
```

Runtime, веса, история чатов и проверочные данные не включаются в Git. Интернет нужен для первоначальной установки зависимостей и скачивания модели; после подготовки локальный чат использует только локальный сервер.
