# День 26 — запуск локальной LLM

Проверочный клиент для локальной Qwen3.5-9B через Ollama. Выполняет три независимых запроса по компьютерной графике разной сложности: roughness и блик, диагностика света и цвета, артефакты normal map после экспорта. Есть CLI и диагностическая веб-страница с фиксированными сценариями. Полноценная интеграция в основной чат относится к следующему заданию.

## Требования

- Windows 10/11, Python 3.11+; Python-зависимости вне стандартной библиотеки не нужны.
- Для проверенной конфигурации использована NVIDIA RTX 5070 Ti 16 GB, около 32 GB RAM, Intel i5-12600KF.
- Интернет нужен для первоначального скачивания runtime и весов. Архив Ollama около 1,5 GB, модель около 6,6 GB; дополнительно нужно место для распаковки и временных файлов.

## Установка и запуск

Все команды выполняются из `week_6/task_1` в PowerShell. Установщик скачивает официальный standalone Ollama v0.40.3, проверяет опубликованный SHA256 и распаковывает его в локальную папку `.runtime`. Уже существующая установка не перезаписывается. Системный PATH не меняется.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install-runtime.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\start-runtime.ps1
.\.runtime\ollama-v0.40.3\ollama.exe pull qwen3.5:9b
```

Runtime слушает только `127.0.0.1:11434`; облачные функции отключены через `OLLAMA_NO_CLOUD=1`. Веса хранятся в `.models`. Если порт уже занят, скрипт запуска сообщает об этом и не подменяет работающий сервер. Скрипт запуска печатает PID; его можно использовать для остановки именно этого процесса через `Stop-Process -Id <PID>`.

Проверить сервер и модель, затем выполнить три запроса:

```powershell
$env:PYTHONUTF8 = '1'
python -B check_local.py --runtime-check
python -B check_local.py
```

Для явного сохранения текстов проверочного запуска:

```powershell
python -B check_local.py --save-text
```

Демонстрационная страница:

```powershell
python -B demo_server.py --port 5026
```

Откройте `http://127.0.0.1:5026/` и запустите три сценария по очереди. Каждый запрос реально вызывает локальную модель через `POST /api/chat`. Веб-страница явно работает в режиме сохранения проверочных текстов; это обозначено перед кнопками запуска.

## Конфигурация и учёт

`config.toml` задаёт модель, тайм-аут, параметры генерации и политики. Начальная конфигурация: контекст 8192, лимит ответа 1024 токена, `think=false`, temperature 0.7, top_p 0.8, top_k 20. Клиент этого задания ограничен указанной моделью и loopback endpoint; смена провайдера требует отдельной адаптации.

В `data/requests.jsonl` сохраняются результаты политик, фактические входные и выходные токены, их вычисленная сумма, доступные сведения о кэше, времена API, параметры и статус. CLI по умолчанию не сохраняет тексты; `--save-text` включает их запись. Runtime, веса и ledger исключены из Git.

Плата за токенный API локального исполнения — 0 USD с указанным основанием, датой и режимом обслуживания. Стоимость электричества, оборудования и обслуживания не измерена и остаётся неизвестной. Отсутствующие счётчики не заменяются нулём; reasoning остаётся неизвестным, если отдельный счётчик не сообщён.

Input policy отклоняет пустой или слишком длинный текст до вызова модели. Output policy проверяет завершение, отсутствие ошибки, непустой ответ и отсутствие обрезания по лимиту. При отказе или неизвестном usage пакет останавливается, метаданные сохраняются, скрытого повтора и облачного fallback нет. Инструкция просит отвечать по-русски обычным текстом без Markdown; программной проверки смысла или очистки разметки нет.

## Проверенный запуск

Пример измерений трёх запросов через HTTP API Ollama 0.40.3. Модель: Qwen3.5-9B, GGUF, Q4_K_M; `ollama ps` подтвердил 100% GPU и контекст 8192. Все три вызова завершились непустыми ответами и прошли формальную output policy.

| Сценарий | Входные токены | Выходные токены | Всего | Полное время API |
|---|---:|---:|---:|---:|
| Простой | 176 | 274 | 450 | 94,84 с |
| Средний | 182 | 224 | 406 | 2,34 с |
| Сложный | 211 | 249 | 460 | 2,66 с |

Первый запрос включает холодную загрузку модели около 52,88 с и первоначальную обработку промпта около 37,51 с. Время последующих запросов относится к уже загруженной модели. Эти три измерения не являются полноценным бенчмарком. Ответы показывают работоспособность генерации; профессиональная точность советов отдельно не подтверждена.

Генерация выполнена локальным runtime с собственными весами и отключённым облаком. Проверка с физическим отключением интернет-соединения не выполнялась.

## Тесты

```powershell
python -B -m unittest discover -s tests -v
```

Тесты используют управляемый транспорт и локальный HTTP-сервер. Они проверяют контракт запросов, политики, учёт, ошибки и маршруты; качество реальной модели подтверждается отдельными фактическими запусками, а не этими тестами.
