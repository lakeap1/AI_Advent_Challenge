# День 29 — оптимизация локальной LLM для помощника по Unity

Приложение сравнивает исходную и настроенную Qwen на одном найденном контексте. Оно расширяет [локальный RAG дня 28](../task_3/README.md): использует тот же корпус, embedding-модель, поиск и проверку ответов, добавляет presets и измерение ресурсов. Код дней 27–28 остаётся общей явной зависимостью; эти папки должны лежать рядом с `task_4`.

Оптимизация предназначена для коротких содержательных вопросов по Unity 6/URP. Тематический шаблон требует ответить на все части вопроса, сохранить точные имена настроек, причинные связи, направления преобразований и условия из источников. Готовые ответы контрольного набора в шаблон не включены.

## Параметры

| Настройка | Исходный | Оптимизированный | Эксперимент Q8 |
|---|---|---|---|
| Модель | qwen3.5:9b | qwen3.5:9b | qwen3.5:9b-q8_0 |
| Реальное квантование | Q4_K_M | Q4_K_M | Q8_0 |
| Temperature | 0.2 | 0 | 0 |
| Context window | 8192 | 6144 | 6144 |
| Max output tokens | 1024 | 512 | 512 |
| Seed / think | 42 / false | 42 / false | 42 / false |
| Шаблон | day28-original | day29-graphics-v2 | day29-graphics-v2 |

Настройки находятся в `optimization/config.toml`, шаблон — в `optimization/service.py`. Перед генерацией сервис проверяет digest и квантование установленной модели, идентичность контекста и консервативный бюджет входа. Большой вопрос или контекст отвергается до вызова генератора; обрезанный ответ не считается успешным.

## Подготовка и запуск

Нужны Python 3.11+, Ollama на `127.0.0.1:11434`, модели `qwen3.5:9b` и `qwen3-embedding:0.6b`. Q8 необязательна. Скачанные ранее веса можно использовать повторно.

```text
ollama pull qwen3.5:9b
ollama pull qwen3-embedding:0.6b
ollama list
```

Из `week_6/task_4`:

```text
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe -B -m flask --app app:create_app run --host 127.0.0.1 --port 5029 --no-reload
```

Откройте `http://127.0.0.1:5029/` и один раз нажмите «Построить индекс». Открытие страницы и чтение состояния не запускают модель. При изменении корпуса или модели перестройте индекс. Для собственного каталога данных используйте `app:create_app(data_dir='data/my-run')` и тот же каталог при сравнении.

Выберите «Сравнить исходный и оптимизированный» и задайте вопрос: «В Unity 6 URP пластиковый материал даёт слишком резкий блик. Как изменить Smoothness и какой канал текстуры управляет этим параметром?» Поиск выполнится один раз, ответы — последовательно. В интерфейсе доступны полные тексты, источники, параметры, timings и receipts. История сохраняет результаты для просмотра; каждый новый вопрос независим и не получает скрытого контекста предыдущих вопросов.

## Проверка и воспроизведение

Тесты используют управляемый транспорт и проверяют отказ, остановку после неполного учёта, сохранение receipts после restart, frozen context и read-only импорт. Они не доказывают смысловую правильность модели.

```text
.venv/Scripts/python.exe -B -m pytest -p no:cacheprovider tests -q --basetemp .test-run
```

Проверка интерфейса с управляемыми ответами API не вызывает модель. Для неё нужны Playwright с Chromium. Пакет разрешается обычным способом; при нестандартной установке задайте `PLAYWRIGHT_MODULE_PATH` путём к пакету `playwright`.

```text
node scripts/check-optimization-browser.cjs
```

Контрольные вопросы и эталонные смысловые факты находятся в `../task_3/evaluation/questions.json`. Скрипт сначала сохраняет найденные фрагменты, затем выполняет по три повтора каждого режима с чередованием блоков. Перед блоком он явно выгружает модели без inference, чтобы сбросить prompt cache и заново выделить контекст, и отдельно записывает warmup. Все вызовы, включая warmup, учитываются; warmup исключены из медиан ответов.

```text
.venv/Scripts/python.exe -B scripts/benchmark.py --data-dir data/experiment --output data/comparison.json --repeats 3 --presets baseline optimized --import-index data/local_rag.sqlite3
.venv/Scripts/python.exe -B scripts/benchmark.py --analyze data/comparison.json --output data/metrics.json
```

Первая команда импортирует индекс, построенный выше через UI в `data/`, в отдельный каталог эксперимента. Если вместо него используется совместимый готовый индекс дня 28, замените путь после `--import-index` на `../task_3/data/local_rag.sqlite3`. Импорт читает только index/chunks, проверяет corpus/model identity, не переносит receipts и не меняет исходную базу. Для повторного эксперимента на точно тех же фрагментах добавьте `--snapshots data/comparison.json`; используйте новые output и data-dir, чтобы сохранить предыдущие доказательства.

Необязательное квантование:

```text
ollama pull qwen3.5:9b-q8_0
.venv/Scripts/python.exe -B scripts/benchmark.py --data-dir data/q8-experiment --output data/q8.json --repeats 3 --presets quantized --snapshots data/comparison.json --import-index data/experiment/local_rag.sqlite3
```

Смысловую оценку нужно выполнить по полным ответам и источникам, отдельно от keyword-проверки. `evaluation/manual_review.json` содержит фактическую оценку поставленного прогона и SHA-256 исходных байтов. Объединение оценки с измерениями допускается только при совпадении hash:

```text
.venv/Scripts/python.exe -B scripts/report.py --run data/comparison.json --review evaluation/manual_review.json --q8-run data/q8.json --selected optimized --output data/experiment/selected-report.json
```

Для нового прогона подготовьте новую оценку с его SHA-256. Если Q8 не запускалась, опустите `--q8-run`. Файл `selected-report.json` в каталоге данных показывается как исторический прогон с датой, а не как измерения текущего вопроса.

## Фактический результат

Измерения выполнены на RTX 5070 Ti 16 GiB, Ollama 0.40.3. Финальная серия содержит 15 исходных и 15 оптимизированных ответов на одинаковых frozen-фрагментах, плюс шесть отдельных warmup. Запрошенный контекст подтверждён через `/api/ps` во всех 30 измерениях.

| Показатель | Исходный | Оптимизированный |
|---|---|---|
| Полностью верные смысловые факты | 36/45 (80%) | 39/45 (86,7%) |
| Частичные / неверные факты | 6 / 3 | 6 / 0 |
| Ответы с неподтверждённым утверждением | 3/15 | 3/15 |
| Ответы с нерелевантной меткой источника | 15/15 | 12/15 |
| Запрос генерации с проверкой ответа, медиана | 2,223 с | 2,399 с |
| Генерация токенов (Ollama eval), медиана | 1,650 с | 1,942 с |
| Токенов/с, медиана | 102,6 | 102,0 |
| Resident VRAM модели, медиана | 5559 МиБ | 5491 МиБ |
| Медиана наблюдаемых GPU-пиков по запросам | 8896 МиБ | 8915 МиБ |
| Токенный API успешной серии, включая warmup | 0 USD | 0 USD |

Выбран optimized: он исправил неверный выбор канала Smoothness через `Workflow Mode`, полнее объяснил gamma→linear и shader variants. Это оптимизация качества при меньшем выделенном контексте, а не ускорение: время запроса генерации выросло на 7,9%, resident VRAM снизилась на 1,2%. Скорость декодирования практически не изменилась; более подробные ответы требуют больше генерации.

Остаются ограничения: оба варианта не объясняют явно необходимость bake для Light Probes; optimized слишком уверенно диагностирует несовпадение конвенций normal map по одному симптому. Метки заголовочных фрагментов часто нерелевантны. Все три повтора одного вопроса в каждом режиме совпали побайтно; это не 30 независимых тем. Оценка выполнена по каждому полному ответу и источнику, не по наличию ключевых слов. Итоговые параметры, агрегаты, hash и ограничения сохранены в [evaluation/results.json](evaluation/results.json), полная оценка — в [evaluation/manual_review.json](evaluation/manual_review.json).

Метрики GPU получены выборочным мониторингом всей видеокарты с интервалом около 0,3 с; это не точный максимум или энергия, и фон ОС не изолирован. Resident VRAM относится к выделению Ollama через `/api/ps`, а не ко всей GPU. Python RSS относится только к процессу benchmark, не к RAM Ollama. Время запроса генерации охватывает HTTP `/api/chat` и обработку/проверку ответа. Поиск, проверки metadata и запись receipts находятся вне этого таймера; eval показывает собственно генерацию токенов отдельно.

Q8_0 действительно скачана: 10 449 218 124 байта против 6 550 825 550 байт Q4_K_M. Её первый warmup завершился CUDA-ошибкой `shared object initialization failed`; ответов нет, качество Q8 — NOT RUN. Это не доказательство нехватки VRAM или общего дефекта Q8. Веса сохранены, автоматический повтор не выполнялся.

При сравнении без выгрузки между блоками наблюдалась ошибка `std::bad_alloc` в runtime prompt cache. Представленная серия использует явную выгрузку перед каждым блоком. Финальный шаблон проверялся на тех же пяти development-вопросах: это ограниченный результат настройки, не независимая проверка обобщения.

## Политики, расходы и границы интеграции

Input policy проверяет вопрос и preset до обращения к модели. Output policy проверяет завершение, модель, машинный JSON, допустимые метки и длину. Смысловую истинность, релевантность меток и соблюдение обычного текста программа не гарантирует; это отдельно проверялось по реальным ответам. Машинный обмен остаётся JSON, пользовательский `answer` запрашивается обычным русским текстом с абзацами без Markdown.

SQLite сохраняет фактические input/output/total tokens, доступные cached/reasoning counters, результаты политик, тариф, источник, модель/digest/preset и стоимость. Известный токенный тариф локального API — 0 USD; электричество и оборудование не измерены. Unknown usage/cost остаются неизвестными и вместе с pending receipts блокируют дальнейшие вызовы также после restart. Уже выполненные отклонённые вызовы остаются в учёте. Скрытых повторов и cloud fallback нет. Каталоги неудачных экспериментов сохраняют свои блокировки; отдельный эксперимент не исправляет их задним числом.

Результаты и UI входят в локальный RAG-путь. Профили пользователя, переключаемые стили и state machine задач основного облачного помощника в локальную цепочку пока не подключены. `/day28` сохраняет страницу дня 28, `/chat` — прежний локальный чат; это отдельные маршруты и отдельные журналы. Ранее реализованный облачный агент не объявляется перенесённым в Ollama.
