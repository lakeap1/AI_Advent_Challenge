# Доверенный обработчик ревью на капсуле

Контур использует существующие Python-окружение дня 31, серверный ключ Z.ai и Qwen на loopback. Пользовательский сайт продолжает работать отдельно. Самостоятельный публичный HTTP endpoint и self-hosted GitHub runner не нужны.

## Установка доверенного runtime

Администратор размещает проверенную версию `week_7/task_2/pr_review` и общую библиотеку `week_7/task_1/graphics` в `$HOME/ai-advent-day32/runtime`, сохраняя структуру `week_7/task_1` и `week_7/task_2`. Это доверенная установленная версия; код head PR в неё не копируется. Зависимости берутся из существующего venv дня 31. Каталог `$HOME/ai-advent-day32/data` создаётся с правами 700: в нём отдельный persistent ledger и временные PR indexes. Производственные `service.sqlite3` и `retrieval.sqlite3` сайта не используются для записи.

`review-worker.sh` устанавливается как фиксированная исполняемая команда. Для доступа к ключу Z.ai и общим настройкам он загружает существующий защищённый `$HOME/.config/ai-advent-day31/service.env`. Затем он обязательно загружает отдельный `$HOME/.config/ai-advent-day32/review.env`, который задаёт собственный `GRAPHICS_BUDGET_USD` для ревью. Этот файл должен принадлежать сервисному пользователю, быть обычным файлом с правами 600 и лежать в каталоге `$HOME/.config/ai-advent-day32` с правами 700. Отсутствующий файл, небезопасные права или отсутствие в нём отдельного лимита останавливают обработчик до вызова модели.

Начальное содержимое `review.env`:

```text
GRAPHICS_BUDGET_USD=0.15
```

`0.15` USD — начальный эксплуатационный предел всего контура ревью, а не бюджет на каждый PR. Он применяется ко всем вызовам в постоянной базе ревью и не обнуляется между запусками. Файл настройки не содержит копии API-ключа. При установке проверяются указанные пути и embedding URL. Неизвестный usage останавливает последующие платные вызовы; очистка базы не является способом снять эту остановку.

Общий helper `graphics.validation` и `graphics.hybrid` должны быть одинаковой проверенной версии у чата и reviewer. Обновление кода приложения дня 31 требует обычной резервной копии и перезапуска его app unit; embedding unit, корпус и пользовательская база при таком обновлении не перестраиваются.

## Ключ CI

Для CI создаётся отдельный SSH-ключ, не пользовательский административный ключ. В `authorized_keys` ему назначается fixed command, `restrict` и запрет PTY/forwarding. Например, строка имеет такую форму; публичную часть заменяет администратор:

```text
restrict,command="/home/user/ai-advent-day32/review-worker.sh" ssh-ed25519 PUBLIC_KEY_FROM_DEDICATED_CI_KEY
```

Обработчик не читает `SSH_ORIGINAL_COMMAND` и принимает только bounded JSON из stdin. Вход не может задавать пути установки, shell-команду, модель, API URL, окружение или ключ. Проверка host key обязательна; использовать `StrictHostKeyChecking=no` нельзя. Существующий административный SSH-ключ не нужно передавать GitHub.

В GitHub repository secrets задаются `PR_REVIEW_SSH_HOST` (`user@host`), `PR_REVIEW_SSH_KEY` (отдельный приватный CI-ключ) и `PR_REVIEW_KNOWN_HOSTS` (заранее проверенная запись host key). Ключ Z.ai остаётся только на капсуле.

## Активация CI и проверка

Оба workflow и доверенный код должны присутствовать в default branch. Код и продуктовые документы дня 31, перечисленные в related paths CI driver, также должны быть доступны в Git-ревизиях: готовая установка сайта на капсуле не заменяет эти источники. Незакоммиченные файлы локальной рабочей папки CI не видит; отсутствие необходимого контекста оставляет ревью неполным.

`pull_request` запускает запрос без checkout/секретов. `workflow_run` использует только default-branch код, проверяет актуальные metadata PR и пропускает fork, draft, closed и stale head. PR Git objects читаются как данные. Обработчик получает JSON по SSH, а CI сохраняет только итоговые `review.json` и `review.html` как artifact. Raw source snapshot не публикуется.

Повторная доставка той же идентичности возвращает сохранённый результат без дополнительных модельных вызовов. Незавершённый либо неизвестный предыдущий запуск не перезапускается автоматически. При смене head во время анализа отчёт помечается stale.

Проверка активации — настоящий PR и GitHub run с точными base/head, доступным artifact и фактическими receipts. Локальный replay metadata проверяет обработчик, но не доказывает работу триггера или правильность repository secrets. Ошибка установки/расходов/валидатора даёт неуспех проверки.

## Откат

Отключите workflow и удалите разрешение отдельного CI-ключа. Сохраните receipts и данные ревью для разбора; пользовательские DB/index сайта не менялись. Откат shared helper выполняется вместе с соответствующей версией `service.py`/`retrieval.py` из проверенной резервной копии, без миграции пользовательских данных.
