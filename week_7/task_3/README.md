# День 33 — поддержка в учебном сервисе «Грани»

Поддержка работает в том же чате, что и обучение. `week_7/task_1` содержит сайт, общий ChatService, журнал расходов, корпус и интерфейс; `week_7/task_3/support` — собственную SQLite обращений и ограниченный MCP stdio. Оба каталога нужны рядом. Однострочные команды `/support` дают детерминированный результат без модели. Вопросы проходят общий путь поиска, генерации и одного смыслового валидатора; прежний лимит сайта 1 USD и запрет следующих платных вызовов при неизвестном учёте сохраняются. Реальную доступность внешнего сервиса подтверждает отдельная живая проверка.

## Пользовательский сценарий

`/support Как работают ветки и сохранённые сведения?` отвечает по документам сервиса. `/support /me` показывает свои профиль и память, `/support /status` — наблюдаемый статус. Профиль меняют командой `/support /profile role=QA; level=beginner; goal=понять Unity URP; depth=short`. Сведение исправляют повторной `/support /remember ключ: значение`, удаляют `/support /forget ключ`. Обращение создают `/support /ticket create НАЗВАНИЕ | СООБЩЕНИЕ`, смотрят `/support /ticket list` и `/support /ticket get ID`, дополняют `/support /ticket append ID | СООБЩЕНИЕ`, закрывают `/support /ticket close ID`. После первой строки команды можно добавить естественный вопрос: действие выполняется первым, объяснение проходит общую проверку. Закрытие означает `closed_by_user`, а не решение проблемы или передачу оператору. Неизвестный исход требует сверить своё обращение и квитанцию.

Канонический индексируемый FAQ — `../task_1/corpus/support-faq.md`; `knowledge/faq.md` указывает на него и не является вторым источником. `knowledge/manifest.json` хранит происхождение и хэш. Интерфейс и HTTP контракт описаны в `../task_1/docs/usage.md` и `../task_1/docs/api.md`.

## Локальные проверки

Требуется Python 3.12+ и зависимости обоих заданий. Из `week_7/task_3`:

```text
python -m pip install -r ../task_1/requirements.txt -r requirements.txt
python -B -m unittest discover -s tests -q
python -B -m support smoke --db demo/support-smoke-UNIQUE.sqlite3
```

Smoke проверяет шесть самостоятельных MCP-инструментов с синтетическими данными без модели; путь БД должен быть новым. Тесты сайта запускаются отдельно из `week_7/task_1`. Они подменяют платного провайдера и не доказывают качество живых ответов.

## Поставка

`python -B scripts/package_delivery.py --root REPO_ROOT --output ABSOLUTE_NEW_PATH.tar.gz` создаёт исходный архив с repo-relative путями `week_7/task_1` и `week_7/task_3`. Внутренний `delivery-manifest.json` формата 1 содержит `files: {path: {sha256, size}}`. Архив отказывается перезаписать существующий файл; содержимое ограничено разрешёнными исходниками, документами и FAQ. Приватные базы, секреты, `.git`, demo, raw captures и локальные отчёты исключены. Перед переносом сверьте хэш самого архива и каждый файл с manifest. Распаковывайте в существующий настоящий Git checkout: MCP должен видеть фактическую ветку. Изменение FAQ/корпуса требует перестроения индекса, затем перезапуска только app unit; старые сервисы и данные сохраняются. Подробности — `../task_1/deploy/README.md`.

## Внешняя проверка

Администратор заранее создаёт две отдельные синтетические учётные записи штатной CLI. Приватный JSON-файл вне checkout имеет вид `{"primary":{"username":"...","password":"..."},"other":{"username":"...","password":"..."}}`. Скрипт не создаёт аккаунты. Из `week_7/task_3`:

```text
python -B scripts/live_check.py --run-live --phase prepare --base-url https://HOST --access-file PRIVATE_ACCESS.json --state-file NEW_PRIVATE_STATE.json
# Перезапустить только приложение, не удаляя приватные данные.
python -B scripts/live_check.py --run-live --phase verify --base-url https://HOST --access-file PRIVATE_ACCESS.json --state-file PRIVATE_STATE.json --receipt-file NEW_PRIVATE_RECEIPT.json
```

На Windows системное хранилище доверия Python может отличаться от браузерного. Если сертификат сервера действителен, но штатный urllib сообщает ошибку цепочки, задайте актуальный CA из установленного certifi только для текущего PowerShell-процесса, затем повторите проверку без входа. Проверку TLS и имени отключать не нужно:

```text
$env:SSL_CERT_FILE = python -B -c "import certifi; print(certifi.where())"
```
Без `--run-live` нет сети, чтения доступа и изменения учётных записей. Prepare через внешний HTTPS и реальные login/CSRF создаёт синтетический чат, профиль, исправленное сведение и продолжаемое обращение. Verify после перезапуска читает их, проверяет изоляцию второго actor и выполняет два содержательных ответа при полном известном учёте. В `receipt` остаются вопросы/ответы и ledger для проверки; пароли и ключ API туда не пишутся. Скрипт не меняет бюджет и не делает скрытых повторов. Оценка API-тарифа не равна неизвестному фактическому списанию bundle. Любое незавершённое действие оценивайте по приватному состоянию, не повторяйте его вслепую.

## Ограничения

Технический статус отражает наблюдение, а не гарантию доступности всех зависимостей. Unknown и unavailable обозначают отсутствие подтверждения. Наличие FSM и отдельного смыслового валидатора не гарантирует абсолютную истинность ответа. Оценка расходов по API-тарифу не равна фактическому списанию предоплаченного bundle; оно остаётся неизвестным.
