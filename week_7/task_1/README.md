# Грани — учебный помощник по компьютерной графике

Грани помогает понять материалы, шейдеры, текстуры, освещение и другие темы компьютерной графики. Можно начать с простого вопроса и продолжить уточнениями: «а почему?», «покажи на примере Unity», «а в Blender?». Ответ учитывает разговор, уровень знаний и выбранную глубину объяснения.

Сервис работает как закрытый сайт. Пользователю нужен браузер и выданная учётная запись. Приложение, база данных, корпус документов и поиск размещаются на сервере; GLM вызывается через API Z.ai. Приложение не управляет настоящей сценой Unity и не выдаёт предполагаемые результаты за измерения проекта.

## Возможности

- Отдельные чаты и ветки от выбранной реплики, продолжение разговора после перезапуска.
- Недавние реплики целиком и сводка старой части. Сжатие сохраняет исходную историю.
- Раздельные профиль, сохранённые сведения пользователя и условия конкретной ветки.
- Поиск по материалам о графике, Unity и Blender с указанием использованных источников и версий.
- `/help` о самом сервисе по README и документации; текущая Git-ветка получается через настоящее MCP-соединение.
- Проверка черновика до показа и сохранение расходов всех этапов, включая отклонённые ответы.

Примеры вопросов и управление памятью описаны в [руководстве](docs/usage.md). Устройство приложения — в [architecture.md](docs/architecture.md), HTTP API — в [api.md](docs/api.md).

В браузере пользователь входит с выданной учётной записью, создаёт разговор и задаёт вопрос. «Ответвить отсюда» у реплики создаёт ветку; панели дают доступ к профилю, памяти, условиям, источникам и учёту. История и ветки остаются доступными после обновления страницы. Ответ появляется только после проверки; если он отклонён, черновик не показывается.

## Размещение

Требуются Python 3.12+, Git, Ollama с моделью `qwen3-embedding:0.6b`, ключ Z.ai и постоянный каталог данных. Для внешнего доступа нужны HTTPS и закрытая учётная запись. Файлы ключей, паролей, базы и загруженного корпуса исключены из Git.

Зависимости устанавливаются из `requirements.txt` в отдельное виртуальное окружение. Обязательные переменные окружения: `ZAI_API_KEY`, `GRAPHICS_SECRET_KEY` со случайным значением длиной не менее 12 символов, `GRAPHICS_DATA_DIR` и `GRAPHICS_REPO_ROOT`, указывающий на настоящий checkout Git. `GRAPHICS_EMBEDDING_URL` задаёт локальный адрес Ollama. `GRAPHICS_PUBLIC_ORIGIN` задаёт точный внешний HTTPS-адрес для проверки Origin за reverse proxy. Файл `.env.example` содержит только названия и безопасные примеры; приложение получает значения из окружения процесса. Пустой ключ сессии останавливает запуск.

Основной процесс запускается через `server:app` в Gunicorn на `127.0.0.1:5031`. Примеры отдельных systemd units и настройки HTTPS находятся в `deploy/`. Сервис embeddings слушает только loopback. MCP работает через stdio и не открывает сетевой порт.

[Подробное размещение](deploy/README.md) описывает установку, закрытую учётную запись, наполнение корпуса, запуск сервисов и обновление.

Перед использованием загрузите корпус по `corpus/manifest.json` и постройте индекс. Манифест хранит источник, версию, язык, область применения и условия использования. Полные тексты внешних документов сохраняются в приватном `data/corpus/`, а индекс — в `GRAPHICS_DATA_DIR`. После изменения документов или модели индекс нужно перестроить. Подробные команды администратора приведены в документации API и размещения.

Администратор создаёт закрытого пользователя командой `python -m graphics.cli create-user USERNAME`; пароль дважды вводится интерактивно. После подготовки корпуса и локальной embedding-модели рекомендуется `python scripts/index_corpus.py`: постоянный кэш позволяет продолжить прерванную индексацию по точному тексту, модели, digest и размерности. Режим `python scripts/index_corpus.py --warm-cache` заранее считает доступные векторы, но ещё не публикует полный индекс. Команда `python -m graphics.cli index` тоже строит полный индекс без постоянного кэша. Открытой регистрации нет. Веб-процесс запускается как `server:app` и должен получать секреты из окружения service manager. Для локальной проверки с явным временным ключом можно вызвать `app.create_app(settings, store, service)` и передать тестовый сервис вместо живой модели. Такой тест не подтверждает работу GLM.

## Модели и расходы

Генерация, подготовка запроса, фильтрация, сводка и отдельная смысловая проверка используют `glm-5.3-flash`. Локальные embeddings Qwen имеют 1024 измерения; поиск объединяет cosine similarity и BM25 через RRF. Выбранная конфигурация развивает решения недель 2–5 без цепочки импортов между заданиями.

Фактические токены берутся из ответа провайдера. Стоимость в USD оценивается по явно сохранённому тарифу обычного API; фактическое списание bundle может быть неизвестно. Неизвестный usage блокирует следующие платные вызовы. Смысловая проверка уменьшает риск ошибки, но не гарантирует истинность каждого утверждения.

## Проверка

Из каталога задания выполните `python -B -m unittest discover -s tests -v` в окружении с установленными зависимостями. Проверки с подставными сетевыми ответами проверяют код и контракты; они не являются доказательством качества живой модели или доступности внешнего API.

Модульные проверки запускайте в отдельном окружении без производственных секретов и `GRAPHICS_PUBLIC_ORIGIN`: тестовый HTTP-клиент использует собственный адрес. Для живой проверки, напротив, требуется окружение развёрнутого сервиса и явный флаг `--run-live` у соответствующего проверочного скрипта.
