# Размещение закрытого сайта

Скрипты рассчитаны на Linux с systemd, отдельный сервисный аккаунт и каталог `$HOME/ai-advent-day31`. Приложение находится в настоящем Git checkout `$HOME/ai-advent-day31/repo/week_7/task_1`, окружение Python — в `$HOME/ai-advent-day31/.venv`, постоянные данные — в `$HOME/ai-advent-day31/data`. Не заменяйте Git checkout распакованным архивом без `.git`: MCP не сможет получить настоящую ветку.

## Окружение и зависимости

Установите Git, Python 3.12+ с venv, curl и Ollama, поддерживающую `/api/embed` для `qwen3-embedding:0.6b`. Создайте venv, затем установите зависимости:

```sh
python3 -m venv "$HOME/ai-advent-day31/.venv"
"$HOME/ai-advent-day31/.venv/bin/python" -m pip install -r "$HOME/ai-advent-day31/repo/week_7/task_1/requirements.txt"
```

Создайте приватный каталог `$HOME/.config/ai-advent-day31` с правами 0700 и файл `service.env` с правами 0600. Заполните значения из `.env.example`; ключ Z.ai и случайный `GRAPHICS_SECRET_KEY` не должны попадать в Git или командную строку. `GRAPHICS_REPO_ROOT` должен указывать на настоящий checkout. Задайте `GRAPHICS_PUBLIC_ORIGIN` равным внешнему HTTPS origin. Сам файл `.env` автоматически не загружается приложением.

Для администраторских команд загрузите защищённый env в текущий shell без вывода его содержимого:

```sh
set -a
. "$HOME/.config/ai-advent-day31/service.env"
set +a
cd "$HOME/ai-advent-day31/repo/week_7/task_1"
```

## Embeddings и корпус

Модель запускается на loopback `127.0.0.1:11436`. В этой конфигурации `setup-runtime.sh` использует существующий runtime предыдущего задания и только его embedding manifests/общие blobs; старые units не останавливаются. Для другого сервера сначала установите отдельный Ollama runtime и модель, затем адаптируйте путь бинарника и `OLLAMA_MODELS` в `ai-advent-day31-embedding.service`. Наличие только имени модели в списке не заменяет успешный `/api/embed`.

```sh
bash deploy/setup-runtime.sh
"$HOME/ai-advent-day31/.venv/bin/python" scripts/ingest_corpus.py
"$HOME/ai-advent-day31/.venv/bin/python" scripts/index_corpus.py
```

Первое построение CPU-индекса может занять значительное время. `scripts/index_corpus.py` сохраняет векторы документов по точному тексту, модели, digest и размерности; повторный запуск использует только совместимые записи. Можно заранее выполнить `--warm-cache`, пока готовятся собственные документы: это не публикует частичный индекс. После подготовки всех файлов обычный запуск строит полный индекс атомарно. Изменения документов требуют перестроения; изменение модели/digest не использует старые векторы.

Тексты внешних источников загружаются в приватный `data/corpus/` внутри каталога приложения, индекс и SQLite — в `GRAPHICS_DATA_DIR`. Не заменяйте корпус симлинком за пределы каталога приложения. Манифест хранит версии, происхождение и лицензии; полные тексты в Git не входят. При недоступности источника сохраните ошибку, устраните причину и повторите явный запуск; фиктивный текст вместо источника не подходит.

## Пользователь, постоянный запуск и HTTPS

Создайте учётную запись; пароль вводится дважды интерактивно:

```sh
"$HOME/ai-advent-day31/.venv/bin/python" -m graphics.cli create-user owner
bash deploy/install-app.sh
```

Проверьте `loginctl show-user "$USER" -p Linger`: для запуска пользовательских units после перезагрузки без входа аккаунт должен иметь linger. На сервере с уже настроенными пользовательскими сервисами сохраните существующую конфигурацию. При отсутствии linger администратор включает его для выбранного аккаунта.

`install-app.sh` запускает только новый `ai-advent-day31.service` на `127.0.0.1:5031`. Для выбранного IP администратор запускает `sudo bash deploy/install-https.sh IP_ADDRESS`; скрипт устанавливает отдельный nginx site, получает short-lived IP-сертификат через Certbot и включает таймер продления. Сначала убедитесь, что порты 80/443 свободны либо существующая конфигурация допускает этот site. Используйте настоящий публичный IPv4 без покупки домена. HTTPS-сертификат по IP требует частого автоматического продления.

Проверки: `systemctl --user is-active ai-advent-day31.service ai-advent-day31-embedding.service`, внешний `GET /healthz`, вход через HTTPS, отказ анонимному `/api/bootstrap`, затем содержательный вопрос и `/help`. `certbot renew --dry-run` проверяет будущий процесс продления; таймер и успешный выпуск проверяются отдельно. Не отключайте проверку сертификата у клиента ради успешного результата.

## Обновление и учёт

Канонический пакет для дня 33 создаёт `week_7/task_3/scripts/package_delivery.py`: он сохраняет пути `week_7/task_1` и `week_7/task_3`, включая общий чат, модуль поддержки, документы и канонический FAQ. Внутренний `delivery-manifest.json` содержит SHA-256 и размер каждого файла. Сверьте manifest с байтами архива до копирования; распаковывайте поверх настоящего Git checkout, сохраняя `.git`, реальную ветку, приватные env/базы и прежние сервисы. Архив отказывается перезаписывать существующий выходной файл. После обновления FAQ/манифеста перестройте индекс и перезапустите только app unit. Зависимости сайта берутся из `task_1/requirements.txt`, поддержки — из `task_3/requirements.txt`.

Живая интеграционная проверка дня 33 разделена на `prepare` и `verify`: `task_3/scripts/live_check.py --run-live --phase prepare|verify --base-url https://... --access-file PRIVATE.json --state-file PRIVATE.json` (для verify также `--receipt-file PRIVATE.json`). Администратор заранее создаёт две отдельные синтетические учётные записи штатной командой, а приватный access JSON содержит `primary` и `other`, у каждого `username` и `password`. Prepare использует настоящий внешний HTTPS, login/CSRF и создаёт профиль, память и обращение через тот же чат. Затем можно перезапустить app unit. Verify проверяет сохранённое состояние, изоляцию второго пользователя и выполняет два реальных содержательных ответа при полном известном учёте и прежнем лимите. Без `--run-live` скрипт не обращается к сети и не читает файл доступа. Логи не должны содержать пароли; приватные state/receipt храните вне checkout. Скрипт не создаёт аккаунты и не меняет бюджет.

Прежний упаковщик дня 31 `scripts/package_deployment.py --output data/deployment.tar.gz` включает только task_1 и недостаточен для поддержки дня 33. Он создаёт архив только разрешённых исходников: без `.git`, env, базы, загруженного корпуса и demo. Он предназначен для обновления кода поверх существующего checkout, а не замены Git-контекста. После переноса проверьте хэш, распакуйте в каталог задания, при изменении документов перестройте индекс и перезапустите только новый app unit. Перед обновлением сохраняйте нужную резервную копию данных выбранным администратором способом.

Живые проверки `scripts/live_check.py --run-live` и `scripts/calibrate_context.py --run-live` используют настоящий API и общий ограничитель бюджета. Они создают отдельные тестовые аккаунты и сохраняют приватные квитанции в `GRAPHICS_DATA_DIR`. Без явного флага платные вызовы не выполняются. Полные тексты вопросов/ответов этих проверок сохраняются как целевые материалы проверки, а не ради одного учёта расходов. Оценка API-тарифа не подтверждает фактическое списание bundle.
