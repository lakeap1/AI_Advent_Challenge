# День 3 — разные способы рассуждения

Локальное веб-приложение решает одну задачу о мосте через OpenAI API четырьмя способами. На странице только ответы и промпты; сравнение находится ниже в этом README. Реальные ответы и их проверки сохранены в results/; новые запросы для их просмотра не нужны.

## Задача и подход

Пять человек со временем перехода 1, 3, 6, 8 и 12 минут должны перейти мост ночью. На мосту одновременно не более двух человек, единственный фонарь обязательно переносится, скорость пары равна скорости более медленного. Все начинают на одном берегу с фонарём. Требуется минимальное время и последовательность переходов и возвратов.

- Прямой ответ: исходное условие без инструкций о способе рассуждения.
- Пошаговый: то же условие плюс «Решай пошагово».
- Метапромпт: первый вызов составляет промпт без решения; второй получает этот промпт и исходное условие. Промежуточный текст сохраняется.
- Эксперты: один системный промпт с тремя ролями. Математик обосновывает минимум, планировщик отслеживает берега и фонарь, скептик проверяет ограничения и альтернативы. Каждый даёт отдельное решение.

Стек: Python 3.10+, Flask, официальный OpenAI Python SDK и Responses API. Во всех пяти вызовах одна модель gpt-5.6-luna и reasoning.effort=high (включая оба этапа метапромпта), без истории, инструментов или подмешивания ответов других способов. Во всех запросах по просьбе пользователя действует одинаковое требование обычного русского текста без Markdown. Это общее ограничение формата, в том числе для прямого ответа; полностью пустого системного промпта теперь нет. Модель сохранена по выбору пользователя. Инструкция «пошагово» меняет промпт, но не параметр reasoning.effort.

## Запуск в PowerShell

Из папки задания:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Впишите свой ключ в OPENAI_API_KEY в локальном .env, затем:

```powershell
.\.venv\Scripts\python.exe app.py
```

Откройте http://127.0.0.1:5003. Ключ также можно передать через переменную окружения сервера. Приложение не зависит от других заданий. Локальный .env не входит в Git; не перезаписывайте свой существующий .env командой копирования при повторной установке.

Кнопка «Открыть последние ответы» показывает последние сохранённые ответы по каждому способу (они могут быть из разных запусков). «Запустить четыре способа» выполняет пять новых оплачиваемых запросов последовательно. Ожидание API ограничено 300 секундами на операцию SDK, автоматические повторы отключены. Ответ показывается целиком после получения; streaming и искусственного набора нет. Точный запрос, промежуточный промпт, время и usage доступны в интерфейсе и JSON.

## Проверка и результат

```powershell
.\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider
```

Проверка 2026-09-07: 23 теста прошли. Дополнительно проверена передача reasoning.effort=high во всех пяти вызовах и сохранение этого параметра в результатах. Покрыты точный минимум, недопустимые и неполные маршруты, ошибочная сумма, допустимый неоптимальный маршрут, только общее требование формата в прямом запросе, два вызова метапромпта, сохранение оригиналов и сохранение первого оплаченного вызова при ошибке второго. Незавершённые метапромпты сохраняются отдельно в results/failed/ и не участвуют в сравнении.

Эталон вычисляется алгоритмом Дейкстры по состояниям «множество людей на другом берегу + сторона фонаря» — не более 64 состояний. Ребро — перенос фонаря одним или двумя людьми со временем самого медленного. Алгоритм находит минимум 29 минут; этот результат в API-запросы не включается.

Ответы сохраняются без исправления ошибок модели. Форм проверки и таблицы сравнения в интерфейсе нет. Для этого сравнения итоговые маршруты вручную перенесены из исходных ответов в сохранённые reviews и проверены функцией check_route из bridge.py. Проверка учитывает людей на обоих берегах, сторону фонаря, допустимость каждого хода, завершённость и сумму времени. Ручная разметка отдельно от оригинала; она не является автоматическим пониманием текста.

Прогон 2026-09-07 по местному времени с reasoning.effort=high во всех пяти успешных вызовах. Имена файлов используют UTC (20260906). После ошибки второго этапа метапромпта повторён только второй вызов, первый успешный промпт сохранён. Таблица учитывает время и токены успешных вызовов; ожидание неудачных попыток в неё не входит, возможный расход неудачных запросов неизвестен.

По итоговым маршрутам наиболее точны пошаговый способ, метапромпт и все три эксперта: минимум 29 минут подтверждён проверкой. Среди этих способов пошаговый использовал меньше времени и токенов в данном прогоне. В usage учитываются и reasoning-токены; длина видимого ответа не отражает весь расход.

Прямой ответ ошибочно отправляет человека 3 повторно с левого берега и утверждает, что перебор подтвердил 27 минут. Модель не вызывала инструмент перебора, поэтому такое утверждение не является доказательством исполнения алгоритма.

Пошаговый ответ даёт правильный маршрут, но сравнение двух стратегий само по себе не доказывает охват всех вариантов. Метапромпт даёт другой допустимый маршрут, меняя местами первые возвраты людей 1 и 3. При этом в пояснении после четвёртого хода пропущен человек C на левом берегу, а в таблице доказательства перепутаны подписи берегов. Правильный маршрут не означает безошибочность всего объяснения.

Математик и планировщик дают одинаковый оптимальный маршрут. Скептик меняет порядок последних парных переходов, сохраняя 29 минут. Их заявления о полном переборе не являются журналом выполненного инструмента; минимум независимо подтверждён кодом задания. Три эксперта остаются ролями одной модели в одном запросе, а не независимыми агентами.

В предыдущем прогоне с none прямой и метапромпт дали правильные маршруты, а пошаговый и эксперты ошиблись. С high пошаговый и эксперты исправились, но прямой способ ошибся. Это два отдельных набора ответов, а не достаточная выборка для причинного вывода о пользе high или общего рейтинга методов. Дополнительное обдумывание не гарантирует правильность.
