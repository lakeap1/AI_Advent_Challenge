# Задание 1.2 — управление форматом ответа

Один локальный чат с моделью `gpt-4.1-mini` через официальный OpenAI Chat Completions API. Переключатели позволяют сравнить один запрос без настроек и с управлением форматом, длиной и завершением.

## Цель

Отправить одинаковый запрос с разными настройками и показать различия в ответах. Формат сдачи: код и видео.

## Требования и допущения

- Python, зависимости из requirements.txt, браузер и интернет.
- OPENAI_API_KEY с доступом к gpt-4.1-mini в локальном .env.
- Переключатели действуют только на следующую отправку. Одна отправка — один платный API-вызов.
- История отображается в текущей вкладке, но не отправляется модели. Это независимые эксперименты на одном запросе.

## Подход

Python, Flask, OpenAI SDK, HTML/CSS/JavaScript. Все переключатели выключены по умолчанию.

- Формат JSON: инструкция вернуть объект с единственным полем answer — массивом ровно из трёх непустых строк-пунктов. Сервер проверяет JSON и эту структуру. Это инструкция, а не Structured Outputs; нарушения остаются видимыми.
- Ограничение длины: инструкция «не более N слов» от 1 до 1000, по умолчанию 60. Работает с JSON и обычным текстом. Токенный лимит вместо слов не передаётся. Под ответом отдельно выводятся фактические слова, токены API и проверка лимита слов.
- Stop sequence: параметр stop со строкой [КОНЕЦ]. Инструкция требует написать её после ответа на все части вопроса; при JSON — после закрытия объекта. Затем запрашивается контрольное продолжение. API останавливает генерацию на маркере и не возвращает его.

Приложение не удаляет маркер, не обрезает и не переписывает ответ локально. В истории видны настройки, токены, finish_reason и параметры отправленного запроса.

Поле локального запроса max_words задаёт лимит слов; сервер переводит его в инструкцию модели. Словом считается разделённая пробелами часть текста, содержащая букву или цифру; дефис внутри слова не разделяет его. В JSON считаются только слова трёх строк answer, без ключей и скобок. Если структура JSON нарушена, число слов и проверка лимита недоступны, а не показаны как ноль.

## Запуск

Из корня проекта:

```text
cd week_1/task_2
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Если .env отсутствует, скопируйте .env.example в .env и заполните OPENAI_API_KEY. Существующий .env не перезаписывайте.

```text
.\.venv\Scripts\python.exe app.py
```

Откройте http://127.0.0.1:5001. Отправьте запрос с выключенными настройками, затем повторите его с JSON + лимитом, затем отдельно со stop.

## Проверка

Из папки задания:

```text
.\.venv\Scripts\python.exe -m pytest -q
```

Проверено 6 сентября 2026: 47 Python-тестов приложения и документации прошли. Отдельно прошли 3 теста локального рекордера. Тесты сервера проверяют все восемь сочетаний переключателей, валидацию ввода, ошибки API, три пункта JSON, лимит слов и отсутствие локальной обрезки. Они не отправляют платных запросов.

Поддержка stop проверена парой реальных запросов к gpt-4.1-mini: копирование ALPHA<END>OMEGA без stop вернуло всю строку, с stop=[<END>] — только ALPHA. В обоих случаях finish_reason=stop, поэтому само это поле не доказывает срабатывание маркера.
Реальные запросы с лимитом 40 слов и включённым stop: обычный ответ — 40 слов, 103 токена; JSON — три пункта, 31 слово, 87 токенов. Оба ответа прошли проверку лимита, JSON — проверку структуры. Это результат конкретных запусков, а не гарантия соблюдения инструкции моделью.
Текущая версия записана: обычный ответ (303 слова, 655 токенов), JSON из трёх пунктов с лимитом 120 слов (48 слов, 106 токенов), JSON с лимитом 40 слов (35 слов, 76 токенов), отдельно stop (245 слов, 562 токена). Все четыре запроса реальные; проверки JSON и лимита слов пройдены.

## Ограничения

- Лимит слов — инструкция, модель может её нарушить. Превышение видно в проверке; автоматической обрезки или повторных платных запросов нет. Очень маленький лимит может быть несовместим с содержательным ответом из трёх пунктов.
- Условие появления [КОНЕЦ] задаётся инструкцией. Если модель его не напишет, stop не сработает.
- finish_reason=stop используется и для естественного завершения, и для совпадения stop sequence. По одному этому полю причину различить нельзя.
- При выключенном лимите остаются внутренние пределы модели. Запрос ожидается до 60 секунд; timeout клиента не является stop sequence.
- Ответ выводится как обычный текст; реального streaming нет. История исчезает после перезагрузки страницы.
