# День 12 — персонализация помощника по графике и арту

Помощник объясняет материалы, свет, моделирование, композицию и другие вопросы компьютерной графики. Сохранённый профиль автоматически задаёт стиль, формат и личные ограничения при каждом ответе. Это развитие приложения с краткосрочной, рабочей и долговременной памятью: предпочтения не требуется повторять в сообщениях.

Приложение локальное: Python, Flask, SQLite, прямое обращение к Responses API. Код задания самостоятельный, импортов из соседних заданий нет. Именованные профили — отдельные локальные рабочие пространства одного оператора; аккаунтов и авторизации нет.

## Запуск

Python 3.11 или новее. Из папки задания:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

В `.env` задайте `OPENAI_API_KEY`, затем:

```powershell
.\.venv\Scripts\python.exe app.py
```

Откройте http://127.0.0.1:5012. Без ключа работают интерфейс и редакторы, отправка модели вернёт ошибку. Конфигурация находится в `agent/config.toml`: модель `gpt-5.6-sol`, reasoning `medium`, предел основного ответа 1600 токенов. Изменение конфигурации требует перезапуска.

## Профиль и использование

При первом запуске создаётся нейтральный профиль «Основной». Его настройки не считаются известными предпочтениями реального пользователя.

- Стиль: свободный текст, например «Объясняй термины простыми словами, до 100 слов».
- Формат: обычный текст с абзацами (`plain`, по умолчанию), нумерованные шаги без Markdown (`steps`) или явно выбранный Markdown (`markdown`).
- Ограничения: например «Blender/Cycles, без платных аддонов и новых текстур».

Стиль и ограничения допускают пустую строку и до 1000 символов. Все три поля сохраняются вместе: неверное поле отменяет всю операцию. В панели отдельно видны действующие настройки и редактируемый черновик. Для сравнения можно явно создать демонстрационные профили новичка и опытного пользователя.

Выбор профиля действует на все его задачи и диалоги. Другой профиль имеет отдельные сообщения, рабочую память, решения, ветки и расходы. Возвращение восстанавливает прежнее состояние. Выбор общий для вкладок одного запущенного приложения: работайте в одной вкладке либо обновляйте состояние после переключения в другой. Одновременные серверы с одной папкой данных не поддерживаются.

## Память и восстановление

`data/profiles.sqlite3` хранит идентификаторы, имена и выбор. В `data/profiles/<id>/memory.sqlite3` находятся задачи, диалоги, рабочая и долговременная память. `dialogue-<id>.sqlite3` хранит историю, ветки и метаданные расходов конкретного диалога.

Предпочтения представлены версионными записями прежней модели памяти: слой `long_term`, категория `profile`, область `user`, ключи `personalization.style`, `personalization.format`, `personalization.constraints`. Второй копии значений в каталоге нет. Редактор создаёт закреплённые версии; общие команды памяти не могут удалять, переносить или разблокировать их. Старые версии остаются для объяснения прежних запросов.

В этом задании профиль управляется явно: чат не переписывает настройки. Автоматическое извлечение продолжает сохранять условия задачи, устойчивые решения и знания. Предложения модели категории `profile` пропускаются с причиной в метаданных служебного запроса. Устойчивую информацию, которую требуется учитывать как личное предпочтение, внесите в редактор.

Смена задачи сохраняет профиль и меняет рабочую память. Новый диалог той же задачи начинает пустую историю с её рабочей памятью. Решения проекта доступны только задачам с тем же проектом внутри выбранного профиля. После обновления страницы и перезапуска восстанавливаются выбор, предпочтения и диалоги. Для другой папки данных задайте `CHAT_DATA_DIR`. Прежние базы автоматически не импортируются.

Данные и `.env` исключены из Git. Тексты сохраняются для истории и памяти; учёт расходов не создаёт дополнительную копию переписки. Базы не зашифрованы. Каталог, память и журнал находятся в разных SQLite-базах без общей транзакции: авария между сохранением памяти и завершением журнала может оставить обновлённую память при interrupted-запросе с неизвестным расходом.

## Автоматическое применение и приоритеты

Перед каждым пользовательским вызовом агент читает актуальный профиль. Сборщик подставляет в `instructions` только выбранное правило оформления, затем добавляет стиль и ограничения. Общего запрета Markdown при выбранном Markdown нет. Для нейтрального профиля используется обычный текст. Далее передаются выбранные записи памяти, Facts при соответствующей стратегии и сообщения диалога. Профиль применяется даже при отключении справочных слоёв и учитывается в оценке размера запроса.

Приоритет, заданный модели: правила приложения и политики → явная инструкция текущего запроса → актуальный профиль → прежние пожелания из истории и памяти. Просьба «для этого ответа используй обычный текст» временно заменяет Markdown-профиль, сохраняя настройки. При неясном конфликте личных ограничений модель получает инструкцию уточнить намерение.

Извлечение памяти и обновление Facts сохраняют собственные JSON-инструкции. Пользовательский формат к ним не применяется. Дополнительного API-вызова ради персонализации нет. Скрытые повторы и исправление ответа ради соответствия профилю не выполняются.

«Состав запроса» показывает идентификатор профиля и точные использованные версии. После редактирования старая трасса показывает прежние значения. Это доказательство переданного контекста, а не гарантия выполнения всех пожеланий моделью.

## Стратегии контекста

- Sliding Window: последние 6 отдельных сообщений, включая вопрос; вся история остаётся на диске.
- Facts: дополнительный вызов обновляет словарь фактов диалога, передаваемый вместе с последними 6 сообщениями. Он не заменяет рабочую память или профиль.
- Branching: checkpoint и независимые продолжения истории. Рабочая память общая для задачи и её веток; независимые условия требуют другой задачи.

Профиль не обрезается вместе с историей. Сохраняются стратегии дня 10 и модель памяти дня 11; отдельный эксперимент со summary дня 9 остаётся в своём задании. Branching допускает рост истории до ошибки лимита API без скрытого сжатия. Предпросмотр оценивает текст до извлечения, не равен usage API и не гарантирует попадание в окно.

## Пример сравнения

Создайте два различных профиля с одинаковой стратегией и новыми задачами без истории. Задайте один вопрос, не перечисляя предпочтения:

```text
Почему керамический материал выглядит пластиковым и что проверить первым?
```

Сравните объяснение терминов, порядок шагов, формат и соблюдение ограничений. Простая разница формулировок ничего не доказывает. Затем спросите «Как проверить это одним пробным рендером?», измените настройку и отправьте следующий вопрос без её повторения. Сверьте автоматическую передачу по трассе.

В текущей конфигурации используется Sol с reasoning medium. В проверке опытного профиля ответ сохранял заданный Markdown, предел 60 слов и запрет новых текстур. Отдельный вопрос об освещении также получил короткий технический ответ. Это наблюдения на конкретных примерах, а не гарантия выполнения произвольного профиля. Простое требование «объясняй каждый термин» всё ещё может выполняться неполностью: для начинающего полезно явно выбирать объяснение простыми словами без названий узлов.

В примере на Sol/medium первый профиль просил простые слова без названий узлов, аналогию и три шага до 90 слов. Ответ содержал 78 слов, три шага и аналогию. Следующий вопрос без напоминания получил 71 слово и три шага; отдельной аналогии в этом практическом продолжении не было. Технический профиль на исходный вопрос получил Markdown-заголовок и список из 53 слов, без предложений новых текстур, аддонов, смены движка или базового цвета. После изменения стиля на одну фразу и формата на обычный текст тот же исходный вопрос получил 20 слов без Markdown. Новые настройки подтверждены переданным контекстом; история при последнем запросе уже содержала прежний ответ.

## Политики, токены и стоимость

Input policy проверяет непустой корректный UTF-8-текст и предел длины до API. Output policy требует завершённый непустой ответ корректной структуры без отказа; служебные ответы дополнительно проверяются по машинному контракту. Отклонённый ответ не выдаётся как успешный.

Смысл, стиль, число слов и Markdown задаются инструкцией, программно не гарантируются. Выбранный Markdown требует короткого заголовка второго уровня и списка; интерфейс показывает текст ответа с исходной разметкой. Reasoning расходует выходные токены вместе с видимым ответом; слишком малый max_output_tokens может дать incomplete, такой ответ отклоняется без повтора. Приложение не открывает сцены, не выполняет рендер и не анализирует изображения; советы остаются рекомендациями.

Каждый вызов сохраняет фактические input/output/total tokens, cached input, cache write и reasoning при наличии, USD-стоимость, модель, режим, тариф и результаты политик. Сумма диалога включает служебные вызовы и отклонённые ответы с известным usage. Reasoning входит в output и не оплачивается повторно; кеш не учитывается дважды. Неизвестные расходы остаются неизвестными, сумма отмечается неполной. Прерванные запросы не повторяются автоматически.

Тариф и дата проверки указаны в конфигурации со ссылкой на [описание модели](https://developers.openai.com/api/docs/models/gpt-5.6-sol). Расчёт применим к указанной модели, стандартной обработке и поддержанному диапазону входа; это оценка, не счёт провайдера.

## Проверки и файлы

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты используют подставной транспорт: проверяют хранение, переключение, восстановление, атомарность, версии, payload всех стратегий, служебные JSON, политики и расходы. Смысл реальных ответов ими не проверяется; реальные API-вызовы оплачиваются отдельно.

- `app.py`, `profiles.py`, `workspace.py` — HTTP, каталог и рабочие пространства.
- `agent/personalization.py`, `memory.py`, `extraction.py` — профиль и память.
- `agent/core.py`, `config.py`, `config.toml` — агент, поведение и политики.
- `agent/storage.py`, `facts.py`, `tokens.py`, `usage.py`, `transport.py` — история, контекст, учёт и API.
- `templates/`, `static/` — интерфейс.
- `tests/`, `pytest.ini`, `requirements.txt`, `.env.example` — проверки и настройка.
